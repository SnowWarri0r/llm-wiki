# 原生流式契约 · 从训练开始就不等未来

## 一句话

所有模块只读过去；新观测立刻能用；刚生成的结果马上写回历史。

## 为什么不是把离线模型切成小块

离线视频编码器可能为了理解当前帧偷看未来帧；回合制对话会等用户说完一句才开始回答；视频生成器可能整段双向去噪。把这些模块外面套一层流式接口，内部仍在等未来，延迟降不下来，也无法在自己说话时继续听用户。

原生流式契约同时约束三件事：

1. 因果：编码器、Transformer、VAE 与解码器不读取未来。
2. 即时：每个新到的 160 ms 单元立刻进入上下文。
3. 提交：每个生成单元播出的同时写回历史，下一单元能看见自己刚做过什么。

## 三个单元的例子

```text
unit 1：看到用户抬手 → 生成“看向手部” → 写回历史
unit 2：听到“等一下” → 读取 unit 1 的动作 → 停住并倾听 → 写回历史
unit 3：用户继续解释 → 读取前两步 → 改写下一句回应
```

如果第二步只读用户输入、不读模型自己的上一动作，它可能一边“停住”一边继续执行原来的动作，长会话会逐渐自相矛盾。
