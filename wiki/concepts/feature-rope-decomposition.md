# Feature-RoPE Decomposition · 缓存内容不动，滚动时重贴位置

## 一句话

KV cache 保存未旋转的内容 Key；窗口移动时只重算 RoPE 位置相位，不重新跑整块特征。

## 直觉

缓存里的 Key 同时带着“写了什么”和“当时放在哪个抽屉”。长视频不断向前，旧抽屉编号会越来越大，跑出训练见过的范围。Feature-RoPE Decomposition 把纸条内容与抽屉标签分开：纸条只算一次，窗口滚动时换标签。

## 怎么做的

普通 RoPE Key 为：

\[
k_p=R(p)k,
\]

其中 \(k\) 是未旋转内容，\(p\) 是位置，\(R(p)\) 是该位置的旋转矩阵。UniSwap 缓存 \(k\)，需要放到新槽 \(\widetilde p\) 时再算 \(R(\widetilde p)k\)。

滚动历史的局部坐标为：

\[
\widetilde p_i(\tau)=\tau-\tau(h_i).
\]

- \(\tau\)：token 的物理时间；
- \(h_i\)：当前窗口最早的滚动历史块；
- \(\widetilde p_i\)：相对窗口起点的局部位置。

窗口有四个槽：永久首块 sink、两个最近历史、当前块。参考身份也永久缓存，但每个当前块开始前会按固定偏移重新定位，让它与当前生成槽保持训练时见过的相对相位。

## 数字例子

取二维内容 Key \(k=[1,0]\)。旧位置相位为 90°：

\[
R(90^\circ)k=[0,1].
\]

若直接把这条已旋转 Key 当成新位置 0° 的内容，读到的是 \([0,1]\)，地址污染了内容。先反旋回 canonical Key：

\[
R(-90^\circ)[0,1]=[1,0].
\]

再贴新位置 180°：

\[
R(180^\circ)[1,0]=[-1,0].
\]

自检：先去旧地址、再贴新地址，内容一直是同一个 \(k=[1,0]\)。UniSwap 直接缓存未旋转 \(k\)，省掉每次先反旋的步骤。

## 为什么音视频必须共用物理时间

若视频窗口左移一格而音频仍用旧起点，同一声“啪”和画面碰撞会落到不同相位。UniSwap 从共同物理时间轴计算两边坐标，虽然音频和视频 token 速率不同，零点和时间跨度仍一致。

## 边界

- 重贴位置不恢复已经被逐块生成误差损坏的内容；它只防位置外推与缓存地址漂移。
- 保留首块能锚定身份，但远期动作细节仍只来自有限滚动历史。
- 论文实测到 1 分钟；项目页的小时级宣称没有同口径量化表。
