# 自指自改 · 考试考的就是改代码,考得越好越会改自己

## 一句话
把"自我修改"本身设计成系统的下游任务,让"下游能力↑"与"自我改进能力↑"变成同一个数字——这是自加速的前提。

## 直觉
一般 meta-learning 是"教练改学员":教练(元 agent)固定,学员再强也不会反哺教练,收益一阶封顶。自指改法是学员自己当教练:agent 是一个改代码的系统,而"改自己"恰好也是改代码——于是每次让它更会改代码的修改,同时让它更会做下一次修改。飞轮由此可能转起来。

## 怎么做的(DGM 版)
- agent = 一个 Python 代码库 + 冻结大模型;自我修改 = 一次普通的编码任务,对象是自己的仓库;
- 评测用 coding 基准(SWE-bench/Polyglot):基准分数既是下游能力,也是自改能力的代理;
- 对照:ADAS 用固定元 agent 生成下游 agent(教练不进步),DGM 消融显示去掉自指(教练固定)50%→39%;
- 边界:①"coding 分数 = 自改能力"是假设,不是恒等;②当前 DGM 的开放探索循环(档案/选父代)固定不可自改;③大模型本体冻结,改训练脚本是未来工作。
