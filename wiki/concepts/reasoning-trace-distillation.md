# 推理轨迹蒸馏 · 不只抄答案，还抄解题过程

## 一句话
训练学生模型时，把老师的中间解法也当监督，而不只给最终答案。

## 直觉
只给答案像题库末页只有“42”；给推理轨迹则像附上草稿：先识别题型、试哪条路、在哪检查、怎样修正。学生获得的监督更密，但也会继承老师的冗余、错误习惯和敏感信息。

## 怎么做的

答案蒸馏的数据对是：

\[
(q, a)
\]

推理轨迹蒸馏把它扩成：

\[
(q, r_1,r_2,\ldots,r_m,a)
\]

- \(q\)：题目或用户请求。
- \(r_i\)：第 \(i\) 段中间推理 token。
- \(m\)：推理长度。
- \(a\)：最终可见答案。

训练仍可以是 next-token prediction；区别在于监督序列从只含 \(a\)，变成同时包含 \(r_{1:m}\) 与 \(a\)。

## 数字例子

一道题的最终答案只有 20 tokens，隐藏推理有 1,980 tokens：

```text
答案监督长度 = 20
推理 + 答案监督长度 = 1,980 + 20 = 2,000
token 级监督密度约扩大 2,000 / 20 = 100 倍
```

这不等于能力一定扩大 100 倍：不少推理 token 会重复、走弯路或只服务格式。但它解释了为什么高质量真实轨迹通常比同样数量的短答案更有训练价值。

## 关键边界

- “输出风格变像老师”不是“训练时用过老师轨迹”的证明；短前缀也能在推理时改变风格。
- 低困惑度只表示目标模型觉得这段文字顺，不证明它记忆过原文。
- 逐字抽取概率很低，也不能排除分布级、策略级蒸馏。
