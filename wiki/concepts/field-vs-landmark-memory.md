# Field vs Landmark Memory · 平滑摘要与关键帧记忆

## 一句话

固定记忆预算下有两种相反取舍：Field 把一段历史平均成摘要，保住整体连续性；Landmark 挑少数关键时刻原样保存，保住具体事件或场景的精确回忆。

## 用旅行照片理解

- **Field** 像把一天照片做成一张“旅行气氛拼图”：能记住大致天气、色调和路线，但看不清某张门牌；
- **Landmark** 像只保留酒店门口、车站出口、景点入口三张原图：回到这些地方时很好认，但没拍到的小巷完全没有。

## 何时分别合适

| 未来 Query 的注意方式 | 更合适的记忆 | 原因 |
|---|---|---|
| 对一整段过去分散关注 | Field | 组均值能近似这一段的总体信息 |
| 集中寻找某个旧场景 | Landmark | one-hot 选择保留该帧的原始 Key/Value |
| 两种需求混合 | 共享槽位里混合分配 | 接口可行，但分配策略需另行决定 |

## 固定预算意味着必有损失

Field 的每槽来源数会随历史增长，组内细节越来越模糊；Landmark 最多保存与槽数相同的场景，装满后必须淘汰。不存在用固定 `L` 格无损复现任意 `T≫L` 历史的办法；设计的本质是提前判断未来更可能需要“整体”还是“某一点”。
