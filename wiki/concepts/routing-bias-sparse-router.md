# 路由偏置稀疏路由 · 把"选哪些块"的概率加进注意力 logit，让任务损失直接训路由器

## 一句话

块级路由分数过 α-entmax 得稀疏分布，取 top-k；选中块的 log 概率去均值后当偏置加到该块所有 token 的注意力 logit 上，于是解析损失的梯度能穿回路由器，不用辅助蒸馏损失。

## 直觉

稀疏注意力要有人决定"这个 query 该看哪几个块"。常见做法是让一个小路由器模仿全注意力的分布（蒸馏），问题是"像全注意力"和"把字认对"不是一回事。另一种硬 top-k 路由（CSA、MiniMax Sparse Attention）选完就断了梯度，只能靠辅助监督或 warmup。

Unlimited OCR 2 的 Token Sieve 走 DashAttention / HiLS 那条路：路由分数不止用来**选**，还作为一个偏置**参与**最终的注意力 logit。这样"这个块该不该被重视"就和"下一个字预测得对不对"在同一个损失里，路由器直接被任务训。

## 怎么做的

```
候选块 b ∈ C（Page Gate 给的）
  s_b = q̃ᵀ k̄_b / √d                 # 块摘要键打分
  π   = α-entmax(s)                  # 稀疏分布：低分块概率恰为 0
  S   = TopK(π, k)
  β_b = log π_b − (1/|S|) Σ_{b'∈S} log π_b'   # 去均值，只在选中块上

注意力（在 局部窗 ∪ 选中块 上做 softmax）：
  logit_j = qᵀk_j/√d + 1[b(j)∈S]·β_{b(j)}
```

去均值的用意：偏置只表达**选中块之间的相对偏好**，不整体抬高或压低远程块相对于局部窗的权重。

## 数字例子

4 个候选块打分 s = (2.0, 1.0, 0.5, −1.0)，k = 2。

**α-entmax（α=1.5）vs softmax**：

| 块 | s | softmax | entmax-1.5 |
|---|---|---|---|
| 1 | 2.0 | .610 | **.815** |
| 2 | 1.0 | .224 | **.162** |
| 3 | 0.5 | .136 | .023 |
| 4 | −1.0 | .030 | **0** |

entmax 把最差的块压到恰好 0，分布真稀疏；softmax 永远给每块留点概率。top-2 = 块 1、块 2。

**去均值 log 先验**：log π = (−0.205, −1.820)，均值 −1.012 → β = (**+0.807**, **−0.807**)。

**偏置进 logit**。保留集：局部窗 2 个 token（logit 1.0, 0.8）、块 1 两个 token（0.9, 0.3）、块 2 两个 token（1.2, 0.1）。

| | 无偏置 softmax | 加 β 后 |
|---|---|---|
| logit | 1.0, .8 ‖ .9, .3 ‖ 1.2, .1 | 1.0, .8 ‖ 1.707, 1.107 ‖ .393, −.707 |
| 块 1 总权重 | .289 | **.553** |
| 块 2 总权重 | .336 | **.128** |

没有偏置时块 2 里那个 1.2 的 token 单点最强，块 2 整体反而更重；加上路由偏置后，路由器"块 1 更相关"的判断把块 1 的总权重从 .289 抬到 .553。反传时 β 的梯度来自这些 logit，再传回 π、s、k̄_b——路由器就是这样被认字损失训的。
