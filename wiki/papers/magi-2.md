# MAGI-2 Preview · 把视频模型做到 114B，每个 token 只走 6B

Sand.ai 一代 MAGI-1（2025-04）研究的是"视频怎么生成"——切成时间块自回归去噪，能流式续写。二代换了一个问题："视频模型怎么放大"。语言模型那边"加参数、加数据、加算力 → 可预期地变好"已经是共识，视频这边大家也在堆，但从"参数更多"到"动作更复杂、物理更对、音画更同步"这条路一直不清楚。MAGI-2 Preview 的回答分三条腿：架构上用极细粒度的多头 MoE 把总参做到 114B、每 token 只激活约 6B；系统上为这种 MoE 专门做了并行、kernel 和优化器；数据上从"往简单里筛"改成"保留复杂、标准描述"。它是一次中间验证，不是成品：博客里没有一张评测表、没有一条 scaling 曲线、没有一个消融。

## 一句话

**把 token 切成 12 个 256 维的小头，每个头在自己的 256 个窄专家里挑 6 个——跨卡通信只按头分片、形状固定可预分配；再配专门的 kernel 和按"头 × 专家"分批正交化的 Muon，把 3,072 个专家单元的 114B 视频 MoE 训了起来。**

## 它要解决的痛点

- **稠密放大的两堵墙**：训练侧，FFN 加宽或加层会同时放大参数、梯度、优化器状态和每个 token 的计算，100B 级别先撞上的是系统问题；推理侧，视频 token 多、去噪又要跑几十上百步，100B 稠密模型每步全参数参与，延迟和成本没法用。
- **LLM 的 token-choice MoE 直接搬过来不好使**：标准专家并行每层通信量约 ∝ N·k·H（token 数 × top-k × 隐藏维），而且发往哪张卡、每张卡收多少、接收缓冲多大全由当前 batch 的路由结果决定——慢卡拖全队、局部峰值显存 OOM、CPU 要同步动态元数据。视频序列比文本长得多，token 又混着三种模态、不同噪声水平和运动状态，这些波动成了一阶成本。
- **数据过滤陷阱**：早期 ≤7B 的小模型学不会复杂分布，社区就把多镜头、复杂运动、带字幕、复杂音频的样本筛掉。这对小模型有用，但大模型面对的仍是一个被简化过的世界——数据成了更强模型的天花板。

## 核心设计

1. **单流起点（沿用 daVinci-MagiHuman）**：文本、视频、音频拼成一条 token 序列，一个 Transformer 只用自注意力处理，没有多塔、没有交叉注意力。没有沿用 MAGI-1 的时间分块自回归——那会给 100B 分布式训练再加一堆变量。
2. **Multi-Head LatentMoE（[[multi-head-latent-moe]]）**：split 投影把 3,072 维隐状态映射后切成 12 个 256 维子空间；每个头有独立路由器，在自己的 256 个专家里选 top-6；各头输出拼回再过 merge 投影。每个稀疏层 12×256 = 3,072 个专家单元，每 token 激活 12×6 = 72 个。专家是 256 → 1,280 → 256 的 SwiGLU7 小 FFN。40 层里中间 36 层是 MoE，头尾各 2 层稠密。
3. **Hierarchical Head Parallel（[[head-parallel]]）**：跨节点（InfiniBand）只按头的归属交换固定形状的激活切片，每张卡收发多少由头的划分静态决定、缓冲可预分配；路由的不规则被关进每个头的持有者内部。节点内（NVLink）用 ZeRO/FSDP 全分片存专家权重、梯度、优化器状态，当前层按需 gather、算完再 reshard。通信量 ∝ N·H，不随 k 涨。
4. **MagiMoE kernel**：融合路由 + Top-K → 按专家紧凑排布 token → 融合分组专家 FFN → 按路由权重合并输出。路由分数 FP32、专家权重 BF16；up/gate 投影与 SwiGLU7 融合，少物化中间结果。
5. **无辅助损失负载均衡（[[aux-loss-free-load-balancing]]）**：每个路由头独立维护专家偏置，负载统计在单独的 CUDA stream 上异步聚合。推理代码里偏置只参与"选谁"，不参与"权重多大"。
6. **MagiMuon（[[muon-optimizer]]）**：专家权重天然是"头 × 专家"一大批小矩阵；路由门按头分批，专家 up/gate/down 把头和专家展平到 batch 维，每个小矩阵独立做 Muon 正交化，矩阵批在 rank 间分摊。adapter、mHC、attention sink、门控相关参数走 Adam 类更新。
7. **数据：从过滤转向生产 + 精确标注**：保留安全、合规、隐私、严重损坏、去重这些必要治理，但"当前模型好不好生成"不再是准入标准；尽量保留复杂运动、多人互动、镜头切换、长尾主体、字幕和画面文字、复杂音频，并把主体场景、动作互动、镜头时序、对白歌声、环境声音乐、画面文字纳入多模态标注。

## 推理代码里能读到、博客没写的

- **每层的其余部件**：MoE 层除了路由专家，还有一个所有模态共享的专家（中间维 1,280）和一个按模态区分的共享专家（文本 / 视频 / 音频各一份，中间维 1,280），两者每个 token 都走。头尾 4 层（0、1、38、39）的注意力和 FFN 都是三模态各一份权重。
- **注意力**：24 头 × 128 维，Q/K 各自 RMSNorm，带 1 个 attention sink，输出乘一个 sigmoid 门。残差走 mHC（4 路残差流，混合矩阵用 Sinkhorn 归一化 20 次迭代）。
- **路由细节**：sigmoid 打分；偏置加在 sigmoid 之后、只用于选 top-6；被选中的 6 个用原始分数 L1 归一化后再乘 4.9。博客公式把偏置写在 σ 括号里面，和代码不一致。
- **参数账**（按配置复算）：总参 113.84B，其中路由专家 108.7B；激活 5.92B，其中路由专家只有 2.55B，其余 3.37B（注意力 1.51B、split/merge 0.68B、共享与模态专家 0.85B、稠密 FFN 0.30B）每个 token 都要走。
- **推理管线**：文本编码器 Qwen3.5-27B（56 GB）；preview 在 512×896、时间隔帧（相当于 12.5 fps）上用 Flow-UniPC 跑 100 步（shift 7，视频 CFG 5、音频 CFG 7）；refiner（30 层、宽 4,096、全部窗口注意力）把潜变量时间插成 2T−1 帧、空间放大到 1088×1920，按 ZeroSNR 表第 220 档重新加噪（0.839·信号 + 0.544·噪声），再跑 5 步（shift 5，CFG 2），音频不进 refiner；最后用蒸馏过的 turbo VAE 解码。8 张 Hopper，Ulysses 上下文并行 8、专家并行 8；12 个头补到 16 才能平分 8 卡，第 6、7 号卡在 MoE 层只持有空头。
- **提示词**：训练 caption 是长的结构化 JSON（global_layer 管主体、美学、音频基线、静态物体；dynamic_layer 按时间段写镜头与动作），推理时建议先用 LLM 把短提示改写成这个格式。

## 关键数字

- 114B 总参 / 约 6B 激活；40 层，宽 3,072；12 头 × 256 专家 × top-6；专家 256→1,280→256。
- 每层 3,072 个专家单元，激活 72 个；每头组合数 C(256,6) ≈ 3.7×10¹¹。
- 10 秒、512×896 的 preview：32 个潜变量帧 × 32×56 = 57,344 个视频 token + 250 个音频 token；refiner 阶段 63×68×120 = 514,080 个视频 token。
- 权重共 307 GB；推理 100 + 5 步，蒸馏版"即将发布"。
- 评测：博客零评测表。媒体报道提到 Artificial Analysis 图生视频榜第六、10 秒 1080p 约 0.5 元成本，均非博客内容。

## 我的批注 / 疑问

- 这份"技术报告"就是一篇长博客：讲清了架构和系统思路，但没有任何定量结果。最值钱的东西其实在推理代码里——共享专家、模态专家、mHC、sink、偏置只管选择、4.9 的路由缩放、refiner 的窗口注意力，博客一个字没提。
- "6B 激活"容易被读成"6B 的 MoE 专家"。按配置复算，路由专家只占激活的 43%；每个 token 固定要走的部分（注意力、split/merge、两类共享专家、头尾稠密层）有 3.37B。所以和"6B 稠密模型"比算力是对的，但别以为 6B 都花在"挑出来的专家"上。
- 多头 MoE 的真正收益在通信形状，不在 FLOPs：跨卡流量从 N·k·H 变成 N·H 只是 k 倍的常数，更关键的是形状静态、缓冲可预分配、不需要 CPU 同步路由元数据。这和 DeepSeek 那条"token 整体路由 + 节点限制路由"的路线是两种答案。
- 代价没量化：每个头的专家只看 256 维子空间，表达力和"整 token 路由的宽专家"相比差多少，没有对照实验。博客自己也说受控消融和 scaling 曲线是下一步。
- 推理时 12 个头摊在 8 张卡上只能补成 16 个头，两张卡在 MoE 层空转——训练时头怎么分配到节点、有没有同样的浪费，博客没说。
- "数据过滤陷阱"是个好观点，但"涌现能力"（跨镜头身份一致、对白配字幕特效）只有定性观察，作者自己也标了要更系统的对照实验。
- 没沿用 MAGI-1 的自回归分块是个有意思的退步：为了先把 100B 的放大跑通，把流式生成能力暂时放下了。下一代会不会把两者合起来，值得看。
