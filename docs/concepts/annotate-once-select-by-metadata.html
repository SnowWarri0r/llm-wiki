Concept

先全量标注，后做决定 · 选择只是元数据运算

一句话

贵的标注（相机估计、caption、质量模型）每条 clip 只跑一次；筛选、分层、混比全是对元数据的索引运算，改门限不再烧 GPU。

直觉

数据管线最常见的写法是"边处理边筛"：不合格的当场丢掉。省了存储，但每次想改门限、换配比、救回某类样本，都得把整条 GPU 管线重跑一遍——而且被丢掉的样本连"为什么被丢"都没留下。反过来，把标注和选择拆成两层：标注是物理事实（一次算清、永久入库），选择是政策（随时改、改了只需重索引）。被拒的样本带着全套指标和机器可读的 reject reasons 留在拒收分区里——它们不是垃圾，是换个门限就能复活的候选。

怎么做的（SolarWM 数据引擎的版本）

  • 1.43M canonical clip 全部过完相机估计、caption、质量指标，再按逐源冻结的政策打三互斥标签：xhigh / high / rejected；549k 拒收样本照常发布，reason 机器可读。
  • 三命名空间分离：物理语料（样本+标注）/ 逻辑配方（split、tier 政策、源权重、repeat 因子）/ 模型视图（骨干专属窗口与 latent）。改配方不复制视频，换 VAE 不动数据选择。
  • 门限逐源不对称：高速游戏源不设通用几何/饱和门，Clean 衍生源加更严的重建校验——通用阈值会在一个域里删掉有用轨迹、在另一个域里留下伪影。
  • 规则引用的指标缺失或非有限一律 fail-closed 拒——"keep-rate 掉到 0"更常见的原因是某个标注适配器系统性挂了，而不是门限太严。
