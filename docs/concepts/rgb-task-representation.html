Concept

RGB Task Representation · 把不同视觉答案改写成三通道图像

一句话

不为每个视觉任务重做输出头，而是先把答案编码成 [0,1] 的三通道视频，让同一个 VAE decoder 和同一种 L2 loss 都能处理。

为什么这能减少模型分支

传统多任务模型可能长这样：

共享 backbone
├─ depth head + scale-invariant loss
├─ segmentation head + BCE / Dice loss
├─ normal head + angular loss
└─ camera head + pose loss

RGB 统一后变成：

视频 + “输出深度 / 法线 / 分割”
→ 同一个 DiT
→ 同一个 VAE decoder
→ 三通道目标视频
→ 同一种 L2

它没有让任务差异消失，而是把差异从“网络头和 loss”搬到了“标签编码与解码规则”。

四类目标怎样塞进 RGB

原始目标 原始每像素维数 三通道表示
深度 d 1 预处理后复制为 (d',d',d')
二值 / 软掩码 m 1 复制为 (m,m,m)
表面法线 3 (n_{x},nᵧ,n_z) 分别映射到 RGB
DensePose 坐标 3 三个连续分量分别占一个通道

“复制三遍”不是增加信息，只是适配 VAE 的三通道输入输出接口。

深度为什么要先做中位数归一化

单目视频里，同一张投影可能对应大小不同、距离不同的真实场景，绝对尺度不唯一。GenCeption 先用整段视频的场景深度中位数 m 归一化：

d_i=\frac{D_i}{m}
  • D_{i}：第 i 个像素的原始深度；
  • m：该视频所有有效深度的中位数；
  • d_{i}：去掉整体尺度后的相对深度。

例子：原深度 [2,4,8]，中位数 m=4，归一化后是 [0.5,1,2]。如果整个场景和距离都放大两倍，原值变 [4,8,16]，中位数也变 8，归一化结果仍是 [0.5,1,2]。

为什么还要取对数

远处深度可能比近处大很多，直接线性塞进 [0,1] 会让近处差异挤在很窄范围。论文采用：

d'=\operatorname{clip}\!\left(\alpha\log(d+1),\,0,\,1\right)
  • d：中位数归一化后的非负深度；
  • d+1：避免 d=0 时对零取对数；
  • log：自然对数，把大深度压缩得更多；
  • \alpha：缩放系数，控制近处和远处占多少数值范围；
  • clip(y,0,1)：小于 0 变 0，大于 1 变 1；
  • d'：最终能复制到 RGB 的数值。

论文没有公开 \alpha 的具体选择规则。只为演示计算，假设 \alpha =0.5：

d log(d+1) 乘 0.5 clip 后 d'
0.5 0.405 0.203 0.203
1 0.693 0.347 0.347
2 1.099 0.549 0.549
10 2.398 1.199 1.000

最后一行超过上限，所以被截成 1。

统一 L2 到底算什么

设模型输出 latent 或坐标向量为 ŷ，标签为 y：

L_2=\sum_j(\hat y_j-y_j)^2
  • j：向量里的第 j 个元素；
  • ŷ_{j}：模型预测；
  • y_{j}：监督标签；
  • 平方让正负误差都变成正数，并更重罚大误差。

例如 ŷ=[0.2,0.8]、y=[0.3,0.6]：

(0.2-0.3)^2+(0.8-0.6)^2=0.01+0.04=0.05

如果实现取均值，则是 0.05/2=0.025。GenCeption 论文只写“standard L2”，没有说明最终按元素求和还是求平均。

代价

  • 标签预处理必须可逆或至少能稳定解读；
  • VAE 压缩误差会作用在深度、掩码等非自然图像上；
  • 一个 L2 不等于所有任务梯度天然平衡，任务混合比例仍需调节；
  • 很难自然图像化的坐标任务仍要新增结构。
