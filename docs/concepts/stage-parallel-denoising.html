Concept

Stage-parallel denoising · 不同视频块同时站在不同去噪工位

一句话

把少步去噪的每一步分给一个设备；块 0 做第二步时，块 1 可以同时做第一步，填满流水线后每个节拍都能产出一个干净块。

依赖关系

任务 (b,k) 表示第 b 个视频块的第 k 个去噪阶段。它必须等两件事：

(b,k-1)\rightarrow(b,k),\qquad (b-1,k)\rightarrow(b,k).

第一条保证同一块按噪声→半成品→干净的顺序走；第二条保证本阶段的 cache 已写入前一块。同一条反对角线 b+k=d 上的任务彼此可以并行。

数字例子

假设 5 个块、3 个阶段，每阶段耗时相同为 t：

T_{serial}=5\times3t=15t,\qquad T_{pipe}\approx(5+3-1)t=7t.

自检：第一个结果仍需 3 个节拍，之后每个节拍多完成一块；理想加速 15/7\approx2.14 倍，小于 3 倍，因为开头要填、结尾要排空。真实系统还有通信、负载不均和前缀预填，速度会更低。

为什么每个阶段有自己的 cache

上游 cache 存的是更吵的同阶段历史，下游 cache 存的是更干净的同阶段历史。把下游结果倒写回上游会改变上游训练时见过的条件分布；TaoMate 因此只在窗口边界用最终干净块更新跨窗口前缀和持久记忆。

边界

流水线提高吞吐，不会按相同比例缩短首块延迟；阶段越少、视频越短，填充开销越明显。论文报告的 35 FPS 依赖三 GPU 配置，不代表单卡也实时。
