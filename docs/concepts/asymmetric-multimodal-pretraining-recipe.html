Concept

非对称多模态预训练配方 · 70% 语言、25% 理解、5% 生成

一句话

若语言和看图能力能给画图提供强先验，而画图对前两者的反向帮助较弱，就不必把三种 token 平均分；这篇论文在自己的 1T 网格中找到 $L/U/G=70/25/5$ 的最好折中。

5% 到底指什么

它指预训练样本 token 的分配比例：每 100 个训练 token，约 70 个来自纯文本，25 个来自图像理解，5 个来自图像生成。它不严格等于：

  • 只花 5% 的墙钟时间；
  • 只花 5% 的 GPU FLOPs；
  • 生成损失只占总梯度的 5%。

论文还把生成的 flow-matching loss 乘以 3，因此数据份额和损失权重是两只不同的旋钮。视觉 token 每个 token 的计算成本也未必和文字 token 完全相同。

拿 100 个 token 做一个只为理解口径的例子。若 70 个属于 L、25 个属于 U、5 个属于 G，并且三类样本各自的平均 loss 暂时都设为 1，那么加权三项分别是 $0.70\times1=.70$、$0.25\times1=.25$、$3\times0.05\times1=.15$，总和约 1.10。生成项此时占 $0.15/1.10\approx13.6\%$，已经不是 5%。真实训练里三类 loss 大小和梯度方向还会不同，所以这个例子只说明：样本份额不能直接当成梯度份额。

为什么少量生成仍然不能删成零

理解能提供物体、关系、数量等结构先验，却不能保证模型学会像素级颜色和形状的生成接口。CLEVR 实验里，模型会看“黄色”不等于零样本就会画“黄色”。所以生成份额可以小，但仍要显式存在。

它怎样落到 MoE

大规模模型共有 13.5B 参数，但每个 token 只激活约 1.5B。256 个 FFN 专家里，每个 token 使用 16 个：2 个固定给语言/视觉模态，14 个动态路由。Attention 和归一化保持共享，延续“小实验里共享交流通道、拆开专用计算”的设计。

不要把 70/25/5 当常数

这是 1.5B/2.3B 控制模型、DCLM、SSTK、指定指标和 1T token 网格中的赢家。换成视频、音频、更大模型、不同 tokenizer 或更重视纯图像质量时，最优点都可能移动。它更重要的启发是：先测知识流，再按边际收益分配预算，不要默认均匀混合。
