Concept

Full-Duplex Multimodal Interaction · 全双工多模态交互

一句话

模型说话时仍在听和看，新输入能立刻改变后半句话。

直觉

普通语音助手像对讲机：用户说完，机器才开始处理；机器说话时，用户只能等。全双工更像电话：两边的声音可以同时存在，听到一句“等等，条件变了”，说话的人会马上收住原来的话，改讲新方案。

“全双工”不是“回答得快”的同义词。一个模型可以 300 毫秒开口，却在自己说话期间关掉麦克风；它仍然只是低延迟的轮流说话。真正的全双工至少要同时处理三件事：

  • 继续接收用户音频、视频和环境变化；
  • 继续生成自己的文本与语音；
  • 处理抢话、附和、停顿、改条件和中途取消。

怎么做的

连续对话通常被切成固定时间片。每到一个时间片，系统都重新读一次“刚刚发生了什么”，再决定下一小段要不要继续说：

上一片的对话状态

      + 新到的用户音频
      + 同时刻的视频帧
      + 后台任务新返回的结果
                    ↓
          更新理解与说话计划
                    ↓
     下一小段文本 + 下一小段语音

DuplexOmni 的时间片是 480 ms。它不是先生成完整句子再播放，而是每 480 ms 交付一小段，并在下一片重新看用户有没有插话。

数字例子

假设助手准备说：

我查到上海出发的航班，早上……

时间线如下：

时间 用户新输入 助手下一步
0–480 ms “查上海到洛杉矶” 开始后台查上海航班，同时先回应“我来看看”
480–960 ms 没有新话 继续说“正在查上海出发……”
960–1440 ms “等等，改北京出发” 停掉上海查询，不再续写原句
1440–1920 ms 没有新话 启动北京查询，改口“好，我重新查北京”

若系统要等整句说完才看新输入，改条件至少要晚一整句才生效。时间片把“反应机会”缩到每 480 ms 一次，但它也意味着最坏情况下仍可能晚接近一个时间片才响应。

跟低延迟、流式输出的区别

能力 只说明什么 仍然可能缺什么
低延迟 很快开始回答 说话时可能听不见用户
流式输出 一边生成一边播放 生成计划可能不会被新输入改写
全双工 输入和输出并行，计划持续更新 深度推理仍可能拖慢，需要额外分层
