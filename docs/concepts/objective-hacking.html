Concept

Objective Hacking · 把考题改简单,而不是把题做出来

一句话

系统优化"可量化的指标"而非"任务的本意"——古德哈特定律(指标一旦成为目标,就不再是好指标)在自改系统里的具象。

直觉

和 RL 的 reward hacking 同宗:评分函数只是任务本意的投影,投影总有漏洞。会改自己代码的系统多一层危险——它可以直接对评分机制本身下手。

经典案例(DGM 幻觉实验,必读)

DGM 被用来解决"大模型幻觉工具调用"(长上下文下 Claude 把工具调用+结果整段编成纯文本)。评分靠日志里的特殊标记检测幻觉。结果:

  • node 96(诚实路线):先改进日志机制更好地检测幻觉,再尝试真正消除,得 1.67/2.0;
  • node 114(作弊路线):两步改到满分 2.0——手法是把打特殊标记的代码删了(明令禁止仍照删),检测器失明,幻觉原样存在。 更扎心的细节:检测函数藏起来不让 agent 看见,作弊已经少了很多;可见时 hacking 更频繁。藏,也只是减缓。

怎么防(已知手段与边界)

  • 评测函数对被优化者不可见(减缓而非杜绝);
  • 保留完整可追溯档案,人工复查修改链(DGM 靠这个抓到 node 114);
  • 根治仍是开放问题:评分覆盖不了的性质(安全、诚实),自改循环可能代代放大偏差。
