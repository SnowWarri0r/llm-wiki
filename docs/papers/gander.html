Gander
会插话的全能助手

Hunyuan Speech Team (Tencent) × 浙江大学 × 上海交大 × CUHK × NTU · arXiv v2 (2026-09)

它想当的是一个像真人同事那样共事的 AI：你说话它随时能接、你打断它立刻收声、你"嗯"一声它知道继续讲；它看得见你的摄像头和屏幕；你顺口说一句"帮我把这份代码改了"，它把活儿转给后台慢慢干，自己继续陪你聊，干完用一句口语汇报。要同时做到"毫秒级接话"和"分钟级干活"，一个模型不够，得两个脑子。

先记这一句Gander 把系统拆成前小脑 + 编排 runtime + 后大脑：小脑是 9B 全双工 omni 流式模型，把听到的、看到的、说出的按 1 秒一个 chunk 全部拍平进同一条自回归 token 流，每个 chunk 先预测一个「听 / 说 / 打断」控制 token——接话时机从外挂 VAD 变成模型自己的预测；大脑是免训练即插即用的通用 agent（默认 Codex），小脑用三个结构化工具调用把长活委派过去。模型、代码、数据全部开源。

§ 00先纠正五个容易读错的点

范围

「端到端」只指小脑

标题里的 end-to-end 说的是前小脑这一个模型内生了感知+交互+发声；后大脑是免训练外挂（默认 Codex app server，评测时由 GPT-5.6 驱动）。整机是三件套系统，不是一个 9B 模型包打天下。

出身

基座是 MiniCPM-o 4.5，视觉塔冻结

开源的 9B 小脑从 MiniCPM-o 4.517 初始化；视觉编码器全程冻结、逐位不变，最终 checkpoint 里都不含它。所以 § 11 的视觉理解跌分不能怪编码器退化。

口径

三套实验互不可比

全双工评测走完整链路（含语音合成和 ASR 识别的真实损耗）；口语对话只有小脑、输出按文本打分；omni 理解是纯 turn-based 选择题。三个分数各在各的口径里读，别横比。

争议

Filler 51.6% 别直接当缺陷

Filler 量的是「接话之后、给出答案之前」垫场词的占比。系统把活委派给后台时不能凭空消失，撑场是设计行为——这个数反映的是委派频率。注意这是作者的辩护口径，不是评测方的中性结论。

第五点 · 两个模型别混论文开源的是 9B 研究版 Gander；文中多次提到的 Hy-Realtime18 是腾讯的工业版模型，不在本次开源范围。两者的关系是：鲁棒性数据里有 Hy-Realtime 生产数据回流，scaling 研究也留给它。

§ 01痛点：VAD 流水线撑不起自然对话

今天的语音助手大多是「排队讲话」：外挂一个 VAD01判断你什么时候说完，把整段话切下来喂给模型，模型答完你再说下一句。人和人聊天不是这样的。

真实对话里全是 VAD 处理不了的事：你话说一半停下来想词（它以为你说完了，抢答）；你在它说话时插一句"等等不对"（它听不见，因为它没在听）；你"嗯嗯"附和两声（它把话咽回去，以为被打断）；旁边有人聊天、电视在响（它把别人的话当你的指令）。这些行为的共同点是：判断"该不该接话"需要语义，而 VAD 只有声学——它知道声音停了，不知道话说完没有。

论文由此提出两个根本问题，整篇工作就是对这两问的回答：

问题一

交互能力该外挂还是内生？

打断、抢话、附和、多人、噪音——这些能不能靠 VAD+ASR 拼装出来？论文的立场：不能。交互时机必须是模型自己的预测，才能随模型智能一起变强。§ 07 的 chunk 拍平就是实现。

问题二

一个模型能又快又深吗？

闲聊要毫秒级接话，改代码要几分钟的工具循环——塞进同一个模型，响应速度和推理深度互相打架。论文的立场：拆开。§ 02 的小脑-大脑架构就是实现。

§ 02总览：三件套怎么分工

整机三个组件：前小脑（realtime 全双工02 omni 模型）管连续感知和实时交互；后大脑（通用任务执行 agent）管长程推理和干活；中间的编排 runtime04 管两边的数据传输和任务调度。名字取自人脑分工03：小脑管反射级的快动作，大脑管慢思考。

分工的判据是时间尺度：几秒内能答的小脑自己扛（日常对话、信息问答、简单搜索），要跑几分钟工具循环的委派给大脑（多步推理、外部工具、长程执行）。委派与否由小脑根据当前对话上下文自回归地决定——这本身也是被训练出来的行为，§ 09 的 agentic 数据就是教这个的。

§ 03小脑怎么使唤大脑：三个工具管一生

上一节说小脑"发工具调用委派"，这一节把接口摊开。小脑在输出流里用专用特殊 token 包裹工具调用10，一共三个操作，覆盖任务从生到死的全生命周期：

task_start · 开任务新建一个后台任务，挂到当前用户轮次上。提供的任务描述兼作任务标识，后续追踪、管理、交互都认它。
task_send · 追加输入把用户后续的话路由给进行中的任务。两种模式：main 把新输入并进主任务的执行上下文（"预算改成 500"）；fork 开一个只读旁问（"进行到哪了？"），不动主任务的状态和轨迹。
task_resolve · 裁决四种确定性裁决：cancel 终止主任务；allow_once 单次放行当前操作；allow_session 本任务会话内都放行；deny 拒绝并阻断。小脑只表达决定，状态迁移由 runtime 确定性执行。

传给大脑的输入刻意选了最直白的方案：用户语音的转录文本 + 相关的末帧画面。论文自己列了两个没做的替代（小脑先做一轮推理再转交；让可训练的大脑直接吃完整多模态流），当开放问题留着。大脑干完后由小脑做总结再开口——总结按口语优化，不是往外念任务报告；至于总结该基于大脑的中间执行态还是最终结果，论文把它当成由训练数据和目标场景决定的配方选择，没有定死。

§ 04编排 runtime：两种控制面 + 一个管家

§ 03 的三个工具是"小脑说什么"，这一节是"谁来落实"。runtime 是持久化的执行底座：实时侧管音视频流接入、增量推理调度、模型调用串行化、前缀缓存、限流；任务侧管状态迁移、并发、权限、交付。一个安全细节值得单独记：工具参数绑定传输层确认的真实用户轮次——任务目标以经过认证的用户输入为准，不信小脑自己生成的参数，防的是小脑幻觉出一个任务。

lean 模式

直通：小脑说了算

runtime16 直接执行小脑分类出的任务动作，用户原话直接当大脑指令。控制路径短、延迟低、确定性强、故障点少。代价：推理强度、监督策略、通知粒度在部署时就定死，没法按单个任务的语义动态调；日常中间事件也更容易被直接透传给用户。

coordinator 模式

加一层控制面模型

在小脑和 gateway 之间插一个独立模型，基于可信用户请求和有界系统状态，生成声明式控制计划：推理强度、追问策略、权限策略、交付策略。它只出计划、不执行任务、碰不到文件/shell/网络；产出还要过 gateway 的结构化校验。代价：多一次模型调用的延迟和不确定性。当前只参与 task_start。

Gateway 是 runtime 的持久化核心，用五个实体组织后端执行；不同的大脑通过统一的 worker provider15 接口接入，各自声明能力集（原生转向、只读旁问、用户交互、跨进程恢复、输入模态、上下文获取、并行执行）：

实体是什么
Project长期任务/工作流的持久容器
Task一个用户意图对应的逻辑工作单元
Run任务的一次具体执行实例
WorkerEventworker 执行期间发出的事件
Delivery结果交付给用户的机制与记录

默认 provider 是 Codex app server：一条任务谱系挂一个持久 Codex 线程，可增量更新；用户追加指令直接注入活跃线程，只读旁问在隔离 fork 里执行，不污染主线程和工作区。

§ 05免训练大脑：白嫖上游智能

大脑就是现成的通用 agent（Codex、Claude Code 这类），负责信息检索、代码和文件操作、文档处理等长程工具流。除了自带的文件/命令行/检索工具，它还能调三个 runtime 专属接口：

context_fetch

拉实时上下文

按引用、角色、事件类型、时间范围、字符预算，从当前任务谱系拉取实时上下文、事件和产物——大脑开工后还能回头看对话现场。

memory_search

查跨会话记忆

检索持久化的多模态记忆，跨会话可用。

share

主动回报

把验证过的重要发现、中间进展、纠错信息推回小脑——用户不用等任务跑完才知道进展。

为什么免训练是个卖点大脑不参与训练意味着两件事：换更强的 agent 不用重训小脑（推理能力随上游升级白嫖跟涨）；但代价是脑与小脑之间只能靠 ASR 转录文本 + 末帧画面这条窄管道沟通——大脑看不见完整的多模态现场。论文把"更丰富的双向通信"明确列为 future work（§ 12）。

§ 06感知：两条通路都在抠 token 预算

全双工的约束是硬的：画面密集到达、音频永不停，每一帧每一秒都要过 LLM。所以两条感知通路的设计全在做一件事——把 token 率压到 backbone 消化得动。

拿音频算笔账（公式先亮：\text{token 率}=\text{帧率}\div\text{下采样倍数}）：编码器出 50 帧/秒，MLP 投影做 5× 时间下采样，50\div 5=10 token/秒。一段 60 秒的输入音频只占 600 个 token——留住理解口语所需的音素和韵律线索，同时不让音频独占每个窗口的预算。视觉侧更狠：切片过 SigLIP（对比学习训出的视觉编码器，此处逐切片独立跑）后由 query resampler12 压成每切片固定少量 token，相对原始 patch 网格约 16× 缩减（论文点名许多先行 omni 模型只做 4×），分辨率也压在 448×448 以内。没公开的：每切片具体多少 token、编码器具体型号尺寸——账只能算到倍数这一层。

§ 07chunk 拍平：每一秒都要回答"要不要出声"

这是全篇的核心机制。§ 06 备好了两路感知 token，现在的问题是：怎么组织输入输出，才能让"接话时机"变成模型自己的预测？答案（chunk 拍平06）：取消"用户轮次"这个特权角色——外界输入只是持续被观测的世界状态，模型活在永远在线的环境里，每个 chunk 都要决定不只"说什么"，还有"要不要说、什么时候说"。

三个设计决定和它们各自防的问题：

控制 token 放在内容之前每个 chunk 的输出段开头先预测一个控制 token07 ∈ {listen, speak, interrupt}，然后才轮到文本。"要不要说"和"说什么"解耦成两次预测——论文明说这比把两件事缠在一步预测里得到更稳的全双工行为。§ 10 的实验解读会回到这一点：正因为这个决定和将要生成的回答共享同一份演化表示，它可以拖到语义完整才拍板，而不是声音一停就抢答。
proactive 行为白送模型每秒都在决定要不要出声，那"没人提问、但画面里出事了、模型主动说一句"跟"有人提问、模型作答"就是同一个机制——不需要任何外挂触发器。VAD 彻底出局。
滑窗对账公式先亮：\text{时长}=\text{chunk 预算}\times\text{窗长}，代入 128\times 1\,\text{s}=128\,\text{s}\approx 2 分钟。淘汰最老 chunk，序列长度有界，per-step 推理成本在任意长的会话里保持稳定。
数字例 · 拍平省了多少解码步一场 96 秒对话 = 96 个 chunk。设模型在 30 个 chunk 里说话（其余 66 个只出 1 个 listen token），训练数据把回复语速改写到约 8 token/秒（§ 09），文本输出 ≈ 30\times 8=240 个 token。对照组：若让 LLM 直接自回归语音 token（编码器帧率 50/秒，§ 06），光输出侧就是 96\times 50=4800 步。拍平 + 让 Talker 扛声学（§ 08），把 backbone 的解码步数压了一个数量级——这就是"backbone 留在文本域"的省法。

§ 08发声：backbone 想，两级小解码器说

§ 07 里 speak chunk 产出的是文本 token，还要变成声音。直接让 backbone 自回归语音 token 有两笔账算不过来：语音 token 帧率远高于文本（解码步数暴涨），而且会侵蚀 backbone 的语言能力。所以 Gander 沿用 Thinker-Talker05 分工——backbone 只管想（语义、韵律决策都编码在隐状态里），发声交给两级轻量解码器：

第一级 · 语音 token 解码器（AR）取 backbone 末层隐状态过投影层，和文本 token 一起喂给一个小的自回归解码器，产出离散语音 token。因为韵律、重音、风格已经预编码在隐状态里，这个小模型不用做高层规划，容量全花在细粒度声学上。离散单元用 CosyVoice 一系的监督语义 token13：单码本、低码率，天生适合自回归预测。文本 token 和语音 token 沿共享时间轴交错生成（不是分两遍跑），保证说出的话和正在观测的环境咬得紧。
第二级 · 流式 flow matching 解码器把语音 token 还原成波形：以多模态 system prompt 里携带的参考音频为条件，用条件 flow matching14 重建目标 mel 频谱再渲染成音频。参考音频决定音色——zero-shot 换声，音色不在训练时定死。逐 chunk 因果解码，token 一到就出波形，不等整句——这是全双工低延迟的前提。
和 wiki 里已有页的连线这套两级发声就是 fish-speech / CosyVoice 谱系的标准做法（语义 token + flow matching 声码）；Thinker-Talker 分工另见 概念页。Gander 的增量在于把它嵌进 § 07 的 chunk 流里流式跑，而不是发声机制本身。

InteractionSpeech：把"插话"造出来的四步管线

攒对话内容（两路来源）①从 11.2K 个场景/话题种子（覆盖教育、医疗、出行、金融、客服等 45 类）用 DeepSeek-V4-Pro 扩成多轮口语对话，限制 8–18 轮、累计说话时长 ≤96 秒——保证整段落在小脑 128 chunk 的流式上下文里；②把真实助手日志和公开语料改写成双工形态，先过"口语适配"过滤（丢掉满是 markdown/代码/URL/数学式、或长度信息密度不像人话的轮次——大多数候选被拒），再按五种交互动机之一注入交互事件：追问约束、过程控制、用户纠错、服务入口失败、安全急停。英文数据一半直接生成、一半由已验证的中文对话翻译——只译对话文本，衍生字段全部按英文分词重新解析，打断点按英文语序重选，不从中文硬搬。
标注两种交互事件竞争性打断09：用户在助手说完前插入；助手没说完的后半句保留为"隐藏续写"——文本留着占时间线，但不合成音频，模型只观测真实听者听得到的声学证据，且校验后续用户轮次不引用没听到的内容。支持性附和（backchannel）08：用户短促出声、助手不停顿继续讲。两者的区分是判据强制的：算附和必须嵌在对方话轮内部、≤8 个汉字或 6 个英文词、且命中词表或生成时显式标注；带疑问/请求/否定立场的候选一律降级为普通轮次。附和词从 266 中文 + 170 英文、11 个意图类的双语词表按上下文采样，避免小词表的复读腔。
渲染上时间线只把用户声道用声音克隆 TTS 渲染成音频（说话人从池子里采），助手轮保持文本、按时长占位。每轮标全局起点、时长、重叠区间——打断和附和的时机本身就是显式监督信号，不是拼接的副产品。不发副语言 token，只留两个标记：打断标记框定重叠区，附和标记在合成前剥掉。
质检两道闸规则闸先丢：打断点语言学上不合理的、重叠段退化的、插话内容泄露了没听到信息的、交互没收尾的。幸存者再过 LLM 评审四维（自然度/助手连贯/打断合理/附和合理），任一维不过线就丢。产出 260.8K 条：打断起点在被打断轮里分布很散（不聚在句尾），且大多数插话直接以内容开头而非语气词——防模型把"打断"绑定到几个词汇套路上。

另外三族的要点

音视频交互（1.1M）：从 JoyAI-VL、LiveCC、Streamo 收集，三类任务（流式视频 QA / 旁白 / 主动视觉响应）；先质检过滤，再用 Qwen3.5-297B-A17B 修时间对齐，回复用 DeepSeek-V4-Pro 改写到平均 8 token/秒——在信息量和语音延迟之间取平衡，用户话语用 Qwen3-TTS 合成。agentic 交互：音频侧走种子驱动轨迹合成（任务类/领域/类目/任务族分层采样，覆盖执行、检索、先查后干三类工作流，全生命周期：开任务/追加/改约束/问进度/取消/交付）；omni 侧从爬取轨迹 + 公开 GUI 数据集 + Codex 生成的 GUI 轨迹凑 36K，Qwen3.5 转成结构化状态描述再合成三方对话。鲁棒与负样本：无关视频 = 网络视频×不相干指令；抗干扰和多人数据来自 Hy-Realtime 生产数据——教模型"没人叫你就闭嘴"这件事占了全部语料的 8.5%。

§ 10全双工实验：时机赢麻，任务分垫底，锅在哪

三个读法，一个比一个重要：

时机双指标只能一起读想压抢答率？多等一会儿就行——代价是该接的话也错过（Gemini 3.1：Interrupt 19.2 但 Take-turn 只有 78）。想满勤？声音一停就开口——代价是用户想到一半就被抢（级联：Take-turn 100 但 Interrupt 33，这是外挂端点器只凭声学判断句子完没完的签名式失败）。Gander 两头都不让：100 + 8.0，全场唯一。这正是 § 07"控制 token 先行"的兑现——决定和回答共享同一份演化中的表示，可以等到语义完整才拍板，而不是声学安静就动手。
任务分的锅不在执行层Gander 端到端 Pass@1 0.400 垫底；但最后一行"仅大脑"（跳过小脑和语音通道、拿用户转录直驱同一个 agent 同一套工具）ToolSel 0.934 全场最高、超过 GPT-Realtime 的 0.876。执行层没问题，掉分在两件事上：小脑要自己决定何时委派（路由错了神仙难救），以及打分读的是合成语音的 ASR 转录（RespQual 从 0.740 掉到 0.490 与此吻合）。这两个实验没有分离，但都属于训练配方和部署链路的问题，不用推翻架构。
Filler 51.6% 的正确读法Filler 量的是接话到给答案之间的垫场词占比（定义在 100 场景中不打断且延迟分析给出裁决的 91 个上）。对一个把活委派给后台的系统，等待期撑场是应然行为——这个数反映的是委派频率，不是接话时机的缺陷。当然这是作者的辩护读法；垫场词多本身对用户体验是不是问题，这份评测回答不了。

大脑全程零调用2052 条里大脑一次都没被调——这是设计行为：路由策略只升级长程工具活，不升级自足的问答。选择性正是双层设计不退化成"纯加延迟"的原因；副作用是这张表对大脑执行质量零发言权。

§ 13我的判断与站内连线

这份报告最值钱的三样东西：一个可复用的系统蓝图（小脑-大脑-runtime 三件套，工具接口和 gateway 实体设计得相当工程化，直接就是一份可抄的 agent harness 规格）；一套交互数据的合成方法学（InteractionSpeech 的"隐藏续写不合成"和附和判据，把"全双工行为从哪来"讲得比大多数模型论文清楚）；一组诚实的实验解读（时机双指标要一起读、back-brain-only 消融定位瓶颈、WorldSense 跌分不粉饰）。短板同样明确：任务准确率垫底、训练配方不透明、双脑通信原始。它更像"omni 交互 agent 这个新物种的第一份系统规格书"，而不是一个打榜模型。

站内连线chunk 拍平的思想源头是 Thinking Machines 的 Interaction Models（论文引用的 flattened interaction formulation 即出自该线）；全双工语音一族另见 Moshi（并行双流路线，对照 Gander 的单流拍平）与 PersonaPlex；Take-turn/Interrupt/Filler 的读法在 full-duplex-bench-metrics 概念页；两级发声（语义 token + flow matching）与 fish-speech 同谱系。

附录词汇表

  1. VAD（Voice Activity Detection） — 外挂的"有没有人在说话"检测器，turn-based 系统靠它判断用户话头话尾。只有声学没有语义，是全双工路线要淘汰的对象。
  2. 全双工（full-duplex） — 听和说同时进行：模型说话时仍在听，新输入能立刻改变行为（收声、改口、继续）。对照 turn-based 的"排队讲话"。
  3. 小脑-大脑协同 — 双层 agent 架构：小脑（小而快、需训练）管实时交互，大脑（大而慢、免训练）管长程任务，工具调用当神经。
  4. 编排 runtime — 缝合两层的执行底座：流式数据传输、推理调度、任务生命周期、权限与交付；核心是持久化的 gateway。
  5. Thinker-Talker — 把"理解+思考"和"发声"拆开：backbone 出语义（文本+隐状态），轻量 Talker 渲染语音。Gander 小脑的内部结构。
  6. chunk 拍平（streaming chunk flattening） — 按 1 秒切窗，每窗 = 感知 token + 控制 token + N 个文本 token，串成单条因果序列——输入输出、各模态共用一条时间轴。
  7. 控制 token — 每 chunk 输出段开头预测的三选一：listen（沉默观察）/ speak（本窗说话）/ interrupt（掐掉自己没说完的话）。先于内容，把"要不要说"和"说什么"解耦。
  8. backchannel（支持性附和） — 听者短促出声但不夺麦（"嗯嗯""对"），说话人应继续。判据：嵌在对方话轮内、≤8 汉字/6 英词、命中词表或显式标注。
  9. 竞争性打断（barge-in） — 用户在助手说完前真夺麦。数据里助手没说完的部分保留为"隐藏续写"：文本占时间线、不合成音频。
  10. task_start / task_send / task_resolve — 小脑委派大脑的三个结构化工具：开任务 / 追加输入（main 并入主任务、fork 只读旁问）/ 裁决（cancel、allow_once、allow_session、deny）。
  11. Full-Duplex-Bench v3 — 100 个带工具的口语服务场景，七个指标：ToolSel（工具选择 F1）、ArgAcc（参数正确率）、RespQual（回复满足意图）、Pass@1（工具集合与参数全对的严格二值）、Take-turn（该接话时接上，↑）、Interrupt（抢答率，↓）、Filler（垫场词占比，↓）。
  12. query resampler — 用一组可学习查询向量把一堆 patch 特征压成固定少量 token 的模块；Gander 视觉侧靠它做 16× 压缩。
  13. 监督语义 speech token — CosyVoice 一系的离散语音单元：拿 ASR 监督训练的量化器产出，单码本、低码率，天生适合自回归预测。
  14. flow matching 声码 — 以参考音频为条件、用条件 flow matching 从语义 token 重建 mel 频谱再渲染波形；参考音频决定音色（zero-shot 换声）。
  15. worker provider — runtime 接入不同大脑的统一接口，各自声明能力集（转向、旁问、恢复、模态、并行等）。默认 Codex app server。
  16. lean / coordinator — runtime 两种控制面：lean 直通（快、确定、策略定死）；coordinator 加一个只出声明式控制计划的模型（灵活、多一跳延迟），只参与 task_start。
  17. MiniCPM-o 4.5 — 面壁的开源 omni 模型，Gander 9B 小脑的初始化基座；其 Omni Flow 把多模态输入输出放上统一时间轴，是 chunk 拍平的近亲。
  18. Hy-Realtime — 腾讯的工业版实时交互模型，不在本次开源范围；为 Gander 提供了抗干扰/多人生产数据，scaling 研究也归它。
