Unlimited OCR 2
只看正在抄的那一页

Baidu ERNIE Team · 核心贡献者 Shu Wei, Jingjing Wu, Qunyi Xie · 仓库内技术报告（2026-10-27）

一代 Unlimited OCR 让模型抄书时只记"刚写的 128 个字"，文本那头的 KV cache 不再涨，几十页能一口气抄完。但它每写一个字仍要把整本书的每一页都扫一遍——页数上到几百，每一步的视觉注意力又线性涨回来了。二代把解码器的注意力再换一次：先按"你在抄哪一页"把可看的图缩到那一页，再在候选里按预算挑几个最相关的块。每个字只看固定数量的图，三百页和三页一个价。再配一个分块预填、边界页复用的解码方式，显存也钉死。

先记这一句SR-SWA = Page Gate（候选只留当前页涉及的块，页坐标 0/1 交替所以位置不会爆）+ Token Sieve（块摘要打分 → α-entmax → top-k，选中块的 log 概率去均值后直接加进注意力 logit，路由器被认字损失端到端训）。可见集大小与页数无关：百页级每步比全注意力快 7.0×、比一代 R-SWA 快 5.6×。配合重叠一页的分块解码，峰值 KV 47.00 → 1.77 GB。自建 MarathonDocBench（100 篇、103–300 页）77.06，第二名 Kimi-K3 33.74；MPDocBench 84.59，领先 Qwen3.8-Max 6.3。没有任何消融，块大小 / k / 窗宽全没给。

§ 00先纠正四个容易读错的点

出处

仓库的 arXiv 徽章链到的是一代论文

README 的徽章指向 arXiv 2606.23050「Unlimited OCR Works」，那是 2026-06 的一代报告。二代目前只有仓库里的 Unlimited-OCR-2.pdf（15 页，10-27 放出），没有独立 arXiv 号。本页全部数字取自这份 PDF。

一代的真实水位

MPDocBench 上一代只有 61.89

两代共用一套多页评测后才看清：一代在 ≤30 页的 MPDocBench 上落后一堆通用 VLM（Qwen3.8-Max 78.30），MarathonDocBench 更是因"40 页输入上限"没法报。一代报告里"几十页一次解析"的口径，放到这里要打折。

单页

单页基本持平，不是单页 SOTA

OmniDocBench15 v1.6：94.02 vs 一代 93.92（+0.10），表格 TEDS 还掉了 0.56；同表 TeleOCR 96.91、OvisOCR2 96.47 更高。这篇的价值全在多页。

空白

没有消融，没有超参

Page Gate 单独多少、Token Sieve 单独多少、块多大、k 取几、局部窗多宽、entmax 的 α——正文一个数都没有；README 只说"例如 512 个工作参考 token"。一代 → 二代在 MPDocBench 上 +22.7，其中多少来自 SR-SWA、多少来自新加的 2M 多页数据，拆不开。

三处小错位正文说"Figure 6 汇总主结果"，柱状图其实是 Figure 5；激活参数正文 500M、架构图 570M；一代报告给的是 OmniDocBench v1.5 数字（93.23），本文对比用的是 v1.6（93.92）。

§ 01三道闸：一代关了一道，二代关另外两道

多页解析01的成本有三个独立的维度：解码时每步要看多少文本、每步要看多少图、显存里要放多少图。一代 R-SWA02只关了第一道。

一代卡在哪

视觉 token 永远全可见

R-SWA 的"参考"是视觉 token + prompt，全局可见、永不淘汰。N 页每页 256 个视觉 token（DeepEncoder 16× 压缩后），每个 query 的注意力范围随 N 线性涨；全部页的视觉 KV 又得预填驻留。百页级这两项是主瓶颈，表 2 直接写一代"40 页输入上限"。

人怎么抄

页间稀疏，页内集中

抄到第 150 页时眼睛只盯第 150 页，碰到跨页表格、续行才瞟一眼前一页，不会把整本书摊在脑子里。作者把这叫多页文档的视觉依赖"天生页间稀疏、页内集中"——稠密全局注意力完全没用上这个结构。

替代方案为什么不行线性 / 循环注意力把历史压成紧凑状态，细粒度视觉证据（认字、跨页检索）保不住；硬 top-k 路由（CSA、MiniMax Sparse Attention）选完梯度就断，要辅助监督或 warmup；作者站到 DashAttention / HiLS 那一路：路由分数直接进前向、端到端训。

§ 02全景：骨干不动，只换注意力，再包一层解码

骨干完全继承 DeepSeek-OCR → 一代那条线：DeepEncoder03做 16× 光学压缩，3B 总参、激活 0.5B 的 MoE04解码器。二代改的只有两件事：解码器里所有注意力换成 SR-SWA05；推理时外面包一层分块解码。先把记号钉死：

\mathbf X_t=\mathrm{Concat}(\mathbf V_1,\dots,\mathbf V_N,\ y_{<t})
\mathbf X_t第 t 步解码时模型面对的整条输入序列：所有页的视觉 token 接上已生成的文本。
\mathbf V_1\dots\mathbf V_NN 页各自的视觉 token（每页 256 个）。一代每步全看；二代只看筛出来的。
y_{<t}已生成的转写；一代起就只看最近 n 个（滑窗）。
\mathrm{Concat}直接拼接：视觉在前、文本在后，一条序列进解码器。

SR-SWA 沿块稀疏注意力12的惯例把这条序列切成固定大小的块 \mathbf B_b，路由以块为单位选；每个 query 还保留一个固定的局部窗。块、局部窗、选中块集合这些记号在下面两节各自的公式里再解释。

§ 03Page Gate：候选只留你在抄的那一页

Page Gate06做的事最朴素：query 属于第 g(q) 页，候选块只保留"与这一页有交集"的块。块边界和页边界没对齐，所以一个块可能横跨两页——跨页块照样进候选，这正是跨页表格、续行需要的那一眼。

\mathcal C_{\text{page}}(q)=\bigl\{\,b\ :\ \mathbf B_b\cap\mathbf V_{g(q)}\neq\varnothing\,\bigr\},\qquad \mathbf p_{i,j}=\bigl[\,p^{\text{page}}_i,\ p^{\text{intra}}_{i,j}\,\bigr]
\mathcal C_{\text{page}}(q)query q 的候选块集合：Page Gate 的输出，交给 Token Sieve 继续筛。
\mathbf B_b第 b 个块：序列按固定长度切出来的一段 token；块边界和页边界无关。
\mathbf V_{g(q)}query 所在页 g(q) 的全部视觉 token；块只要和它有交集就留下。
\mathbf p_{i,j}=[p^{\text{page}}_i,\ p^{\text{intra}}_{i,j}]第 i 页第 j 个 token 的位置：页坐标按 0/1 交替（有界），页内坐标单调递增。
位置

页坐标为什么要 0/1 交替

把每个 token 的位置拆成两段：页坐标 + 页内坐标。页内坐标单调递增但有上限（一页的 token 数）；页坐标如果写绝对页号，第 300 页就会出现训练没见过的大数——所以它只按 0、1、0、1 交替，永远有界，长度外推稳。

代价

放弃了"隔了多远"

0/1 交替意味着模型只知道"本页 / 相邻页"的奇偶，分不出第 7 页和第 150 页谁更远。作者在局限里承认稀疏机制不保全局信息，标题层级是短板——两个基准上 HeadingTEDS 都是各类里最低（60.10 / 48.20），和这个设计对得上。

§ 04Token Sieve：按预算挑块，路由器被认字损失直接训

候选缩小了，还要在固定预算里挑。Token Sieve07给每个候选块压一个摘要键，用 query 打分，过 α-entmax08得到一个真稀疏的分布，取 top-k。关键一步在后面：选中块的概率转成去均值的 log 先验，加进注意力 logit——路由器因此在同一个损失里被训，不用辅助蒸馏13。

s_b(q)=\frac{\tilde{\mathbf q}^{\top}\bar{\mathbf k}_b}{\sqrt d},\qquad \boldsymbol\pi(q)=\alpha\text{-entmax}\bigl(\{s_b(q)\}_{b\in\mathcal C_{\text{page}}(q)}\bigr),\qquad \mathcal S(q)=\mathrm{TopK}\bigl(\boldsymbol\pi(q),k\bigr)
\beta_b(q)=\log\pi_b(q)-\frac{1}{|\mathcal S(q)|}\sum_{b'\in\mathcal S(q)}\log\pi_{b'}(q),\qquad \mathcal R(q)=\mathcal L(q)\cup\bigcup_{b\in\mathcal S(q)}\mathbf B_b
\alpha_j(q)=\mathrm{Softmax}_{j\in\mathcal R(q)}\Bigl(\frac{\mathbf q^{\top}\mathbf k_j}{\sqrt d}+\mathbb I\bigl[b(j)\in\mathcal S(q)\bigr]\,\beta_{b(j)}(q)\Bigr)
s_b(q),\ \boldsymbol\pi(q),\ \mathcal S(q)块 b 对 query 的打分、过 entmax 后的路由分布、取 top-k 后的选中块集合。
\mathcal L(q),\ \mathcal R(q)固定的局部窗（最近的输出 token）；保留集 = 局部窗 ∪ 选中块里的全部 token，softmax 只在它上面做。
\bar{\mathbf k}_b块 b 的摘要键：一个块压成一个向量，路由只在块级打分，便宜。
\alpha\text{-entmax}softmax 的稀疏版：低分项概率恰好为 0。所以 top-k 之外的块真的是零概率，log 先验只在选中块上有定义。
\beta_b偏置只表达选中块之间的相对偏好，不整体抬高或压低"远程块 vs 局部窗"。
\mathbb I[\cdot]\,\beta局部窗里的 token 用普通 logit；选中块里的 token 额外加该块的偏置。偏置在 logit 里 → 解析损失的梯度传回 π、s、k̄_b。
打分 → 稀疏分布四个候选块 s = (2.0, 1.0, 0.5, −1.0)。softmax 给 (.610, .224, .136, .030)，谁都不是 0；α-entmax（α=1.5）给 (.815, .162, .023, 0)——最差的块概率恰好为零。top-2 = 块 1、块 2。
去均值 log 先验log π = (−0.205, −1.820)，均值 −1.012；β = (−0.205+1.012, −1.820+1.012) = (+0.807, −0.807)。两个数之和为 0：偏置只管"块 1 比块 2 更该看"，不管"远程块整体比局部窗更该看"。
偏置进 logit保留集 6 个 token 的原始 logit：局部窗 (1.0, 0.8)、块 1 (0.9, 0.3)、块 2 (1.2, 0.1)。加偏置后块 1 变 (1.707, 1.107)、块 2 变 (0.393, −0.707)，局部窗不变。
softmax 对账不加偏置：局部窗 .375、块 1 合计 .289、块 2 合计 .336。加偏置：.320、.553、.128。块 2 里那个单点最强的 1.2 被路由器的判断压下去了。反传时这些 logit 对 β 有梯度，β 对 π、s、k̄_b 有梯度——路由器就是这样被"下一个字对不对"训的，不需要去模仿全注意力的分布。
为什么 entmax 和"只对选中块定义 β"是配套的softmax 下所有块概率都大于 0，top-k 之外的块被硬切掉就有不连续；entmax 让落选块本来就是 0 概率，top-k 只是把"本来就是 0 的"拿掉，log 先验自然只在非零块上有定义。

§ 05可见集账：200 页差 80×，实测每步 7.0× / 5.6×

一代200 页 × 256 = 51,200 个视觉 token 全可见，加 128 滑窗 = 51,328；页数翻倍它翻倍。
二代README 给的例子"512 个工作参考 token"+ 128 滑窗 = 640；200 页是 640，2,000 页还是 640。比值 51,328 / 640 ≈ 80。
实测口径Gundam 模式16、batch 3、每页固定生成 1,024 token，量的是"每步 ms"：全注意力随页数快速涨，R-SWA 局部窗有界但远程视觉范围仍随长度涨，SR-SWA 从短文档到百页基本平。百页级 7.0× / 5.6×。
这张图的"640"是示意块长、k、局部窗宽论文都没给，512 来自 README 的"例如"。曲线形状（线性 vs 平）是论文结论，纵轴具体数字是本页按一代的 256/页和 README 的例子推的。

§ 06分块解码：每步算得省了，显存还得分开放

SR-SWA 管"每步看多少"，不管"显存里放多少"：哪怕每个 query 只看 640 个 token，300 页的视觉 KV 仍得先全部预填出来才能被挑。无限时程解码范式09把文档切成重叠一页的 chunk 顺序跑，复用重叠页的 KV 保续接，非活跃 chunk 的视觉 KV 释放。

切块N 页切成 K 个 chunk，相邻重叠 1 页（K=1 就是不切）。
第一块cache ← ENC(chunk 1 ⊕ q)，解码出 y_1。指令 q 只跟第一块走。
后续每块cache ← 重叠页视觉 KV ⊕ ENC(本块其余页 | 重叠页 KV) ⊕ 上一块末尾 T 个文本 token 的 KV；解码 y_k；本块跑完，视觉 KV 释放。
效果（表 4，百页级）峰值 KV 47.00 → 1.77 GB（26.6×）；B=16 吞吐 360 → 1,315 TPS（3.65×）——显存省下来后同样的卡能开更大并发。代价没报：重叠页在两个 chunk 里各编码一次。

§ 07MarathonDocBench：百页级的尺子是自己造的

现有多页基准最长的 MPDocBench10只到 30 页，也没多少跨页结构。MarathonDocBench11是作者为百页级专门建的。

规模

100 篇 · 103–300 页

205k 个标注版面元素，平均每篇 2,050 个；长度比 MPDocBench 多约一个量级。

结构

跨页文本 / 表格更密

跨页续接出现得更频繁、更密集（论文图 2 只有分布图，没给具体比例）。T-TextEdit、T-TableTEDS 两个指标专门量跨页。

标注

强解析器初始化 + 人工 + VLM 迭代

框、类型、层级、阅读序、跨页续接由强单页解析器初始化再人工精修；文本转写由同一解析器初始化、VLM 迭代精修、分歧人工裁决。初始化用的是哪个解析器没点名。

指标14沿用 MPDocBench 官方协议：文本和阅读序用编辑距离（越低越好），表格用 TEDS，公式用 CDM，图框用 F1，再加跨页的 T-TextEdit / T-TableTEDS，最后聚合一个 Overall。

§ 08数据与训练

语料

2M 多页 + 10M 单页

伪标签来自 MinerU2.5-Pro 和 PaddleOCR-VL-v1.617，按各自擅长的域分工；合成文档管线补版式多样性；VLM 多维特征分析做平衡过滤，让复杂版式分布均匀。多页子集再过 MinerU-Popo 精修 + 启发式规则，把相邻页边界的结构对齐。

配置

1 epoch · 25×8 H800

从一代 checkpoint 起训；全局 batch 1,600，最长 64K token；AdamW + cosine，初始 lr 2.5e-4；冻结 DeepEncoder 和 aligner，只训 LLM；MS-Swift 框架。部署侧分块解码集成进 SGLang18。

读这段要带的问题一代到二代 MPDocBench +22.7，训练数据从一代的 2M（主要单页）换成 2M 多页 + 10M 单页、还加了专门的跨页结构精修——这些和 SR-SWA 一起变的，论文没拆。"SR-SWA 带来多少"目前回答不了。

效率

两条曲线、一张表

每步延迟（Gundam 模式、batch 3、每页 1,024 token）：百页级 7.0× vs 全注意力、5.6× vs R-SWA，SR-SWA 近乎平线。分块解码：峰值 KV 47.00 → 1.77 GB，吞吐 360 → 1,315 TPS。端到端总时间和 prefill 开销没报。

§ 11论文没有告诉我们的事

缺

消融

Page Gate / Token Sieve 各自贡献、SR-SWA vs 数据扩充的贡献，一个数都没有。

缺

超参

块长、k、局部窗宽、entmax 的 α、chunk 大小 W、文本尾长 T 全部未给；"512 工作参考"只在 README 的例子里。

缺

端到端成本

只报"每步 ms"和峰值 KV；总时间、prefill、重叠页重复编码的开销没报。

缺

基准的细节

MarathonDocBench 的初始化解析器没点名；跨页结构"更密"只有分布图没有比例；图 2 文字在 PDF 里是乱码。

作者自己列的局限训练数据多样性有限；稀疏注意力不保全局文档信息，标题层级这类文档级结构理解弱。下一步想引入线性注意力，用常数的每 token 成本保住全局信息。

§ 12定位：三道闸各管一维，合起来才叫 unlimited

一代解决"记多少字"（文本滑窗），二代解决"看多少图"（页门 + 筛子）和"放多少图"（分块解码）。三道闸各管一个维度，读的时候别混成一件事。方法本身不新——块稀疏、query 相关路由、路由分数进 logit 都有出处（DashAttention、HiLS）；新的是把它们装进"参考 + 滑窗"这个 OCR 专用的结构里，再用一个自建的百页基准证明它在别人全部腰斩的地方能站住。

能信的

方向和数量级

每步成本与页数无关、显存与页数无关，这两条有实测曲线和表 4 背书；百页级 77.06 vs 33.74 的差距大到不需要纠结评测细节。权重、代码、SGLang 集成都开源。

要留一分的

归因和单页

SR-SWA 到底值几分没有消融；MarathonDocBench 是自家造的尺子；单页不如更小的专用模型；标题层级是明显短板。

带走的一句人抄书的两条习惯——只记刚写的几个字、只看正在抄的那一页——一代做了前者，二代做了后者；"OCR-3.0"这个名字是作者给的，能不能立住要看别人在百页级复现出来。

术语Glossary

  1. 多页端到端解析 · 把整份多页文档当一个序列到序列任务，一次前向吐出全部转写；区别于一页一图、每页重置记忆的 for-loop 调度。
  2. R-SWA · 一代的注意力：全部参考（视觉 + prompt）全局可见 + 最近 n 个输出 token 的滑窗；文本 KV 恒定但视觉段随页数涨。
  3. DeepEncoder · DeepSeek-OCR 的视觉编码器，SAM-ViT 串 CLIP-ViT，16× 压缩，一页 → 256 个视觉 token；本文冻结不训。
  4. MoE 解码器 3B-A0.5B · 3B 总参、每 token 只激活约 0.5B（架构图写 570M）。
  5. SR-SWA · 稀疏参考滑窗注意力：Page Gate + Token Sieve 构造固定容量的参考集，再并上局部窗；每步成本与文档长度无关。
  6. Page Gate · 候选块只保留与 query 所在页有交集的块；位置编码拆成 0/1 交替的页坐标 + 单调的页内坐标。
  7. Token Sieve · 块摘要打分 → α-entmax → top-k；选中块的去均值 log 概率作为偏置加进注意力 logit，路由器端到端训。
  8. α-entmax · softmax 的稀疏推广（α=1 退化为 softmax，α=2 是 sparsemax）：低分项概率恰好为 0。
  9. 无限时程解码范式 · 文档切成重叠 1 页的 chunk 顺序处理，复用重叠页视觉 KV 和上一段末尾文本 KV，释放非活跃 chunk；显存只装一个 chunk。
  10. MPDocBench · 现有多页解析基准，最长 30 页；指标含文本 / 阅读序编辑距离、表格 TEDS、公式 CDM、图框 F1 和跨页的 T-TextEdit / T-TableTEDS。
  11. MarathonDocBench · 本文自建的百页基准：100 篇、103–300 页、205k 标注元素，跨页结构更密。
  12. 块稀疏注意力 · 把序列切固定块、以块为单位决定可见性的稀疏注意力家族；本文沿用其分块与局部窗惯例。
  13. 路由蒸馏 vs 端到端路由 · 前者让路由器模仿全注意力分布（辅助 KL 损失），后者让路由分数进前向、由任务损失直接训；本文走后者。
  14. TEDS / CDM / 编辑距离 · 表格结构相似度、公式识别指标、文本与阅读序的字符级距离；跨页版本前缀 T-。
  15. OmniDocBench · 单页文档解析基准；本文用 v1.6，一代报告用 v1.5。
  16. Gundam 模式 · DeepSeek-OCR 系列的高分辨率输入模式；延迟实验在此模式、batch 3、每页 1,024 token 下量。
  17. MinerU / PaddleOCR-VL / MinerU-Popo · 产伪标签的两个解析器（按域分工）与做多页结构精修的工具。
  18. SGLang / MS-Swift · 分块解码集成进的推理框架 / 训练用的框架。
