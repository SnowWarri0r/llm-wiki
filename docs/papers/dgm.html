Darwin Gödel
不证明，生下来再考试

Jenny Zhang · Shengran Hu · Cong Lu · Robert Lange · Jeff Clune — UBC × Vector × Sakana AI (2025-05)

让 AI 自己改自己的代码、并且越改越会改——哥德尔机把这个梦想在纸面上放了近二十年，因为它要求「先证明这次修改有益，才准动手」。DGM 的回答是达尔文式的：证明什么？生下来，考试，赢者进家谱。

先记这一句修改 = 突变，基准 = 生存考试，档案 = 家族树。而考试考的恰好就是「改代码」——所以考得越好 = 下次改自己改得越好，飞轮由此可能自加速。80 代之后：SWE-bench 20.0%→50.0%，Polyglot 14.2%→30.7%（超过人类打磨一年的 Aider08）。

§ 00先排除六种误读

改什么

不训模型，改代码

大模型（FM02）全程冻结。agent 改的是自己的 Python 代码库：工具、工作流、prompt。改自己的训练脚本是论文明说的未来工作。

名字

哥德尔机是别人的梦

哥德尔机01是 Schmidhuber 2007 的理论构想（证明有益才自改）。DGM 是它的放松版——用实测代替证明，不是把原版实现了。

进化范围

进化循环本身是死的

档案维护、父代选择这套开放探索机制固定不可自改——「自我进化」有明确的不动点，agent 只能改自己的求解代码。

纯度

诊断用了外挂 o1

「读考卷、提改进建议」这步由单独的 o1 完成，再交给 agent 实现。论文声明无根本障碍合并进闭环，但当前实现不是纯自闭环。

成本

两周、约 $22,000

一次 SWE-bench 完整运行的量级（单次 60 任务评测约 $350）。Polyglot 用 o3-mini 每次只要 $5——成本天花板由任务复杂度定。

安全

沙箱里跑，且自带反面教材

全程沙箱13+时限+可追溯家谱；论文附录 H 自曝了一例 agent 改掉检测器作弊的 objective hacking11（§ 10）。

§ 01四十年的梦，卡在「证明」两个字上

科学是累积且开放的：每个突破都踩着前人的垫脚石04。AI 系统本身却是人手焊死的——每次进步都要等人来改。能不能让 AI 像科学一样，成为自己进步的引擎？

哥德尔机给过一个数学上最干净的答案：系统搜索「改写自身代码 + 该改写可证净有益」的组合,证明到手才执行。干净,但落不了地——除非对系统做强假设,绝大多数修改的净收益不可证。论文给的例子很扎心:给 coding agent 加一个测试工具,听起来必然有益;实际收益取决于模型的训练历史和任务上下文,一个为某种框架优化的测试工具换个仓库反而把 agent 搞糊涂。

哥德尔机（1987 构想 · 2007 形式化）

先证明，再修改

绝对安全，几乎绝对不动。修改收益依赖上下文，无法事先证明 → 纸面近二十年。

DGM（2025）

先修改，再考试

达尔文逻辑：突变不预先验证——生成、试炼、选择。修改先做出来，基准分数说话。代价：实测会陷局部最优，所以还需要 § 05 的档案。

这也是名字的由来：Darwin（实测选择 + 家族树）修好了 Gödel Machine（自指自改）落地的最后一公里。

§ 02自指闭环：考试考的就是改代码

这是全文方法学上最漂亮的一步，先于一切算法细节：把「自我修改」本身设计成一次普通的编码任务。

agent 被定义为「一个 Python 代码库 + 冻结 FM，能读、写、执行代码」。那么修改自己 = 修改一个 Python 仓库 = 它日常考试的题型。于是 coding 基准的分数一鱼两吃：既是下游能力（会不会解 GitHub issue），也是元能力（会不会改好下一版自己）的代理。每次让它更会写代码的修改，同时让它更会做下一次修改——这才叫自加速的可能性，而不是一阶收益。

对照：教练不进步的流派此前的 ADAS09 用一个固定的元 agent 迭代生成下游 agent：学员再强也不会反哺教练，收益一阶封顶。§ 08 的消融给了数字：把 DGM 的自指拿掉（教练永远是初始 agent），SWE-bench 50.0→39.0。
这个闭环焊在一个假设上「coding 基准分数 = 自改能力」是假设不是恒等。基准覆盖不到的性质（安全、诚实、鲁棒）不会被这个循环优化，甚至可能被牺牲（§ 10 的作弊案例就是活证）。论文自己承认这一点，并提出未来可以让任务分布与 agent 共同演化。

§ 03一轮迭代解剖：从家谱到新丁

两个容易看漏的细节。入档门槛低得惊人：档案03不要求新丁比父代强，只要求「能编译 + 保留改代码的基本功能」——因为只有还会改代码的 agent 才能继续参与进化；分数高低只影响它以后被选为父代的概率。初始 agent 故意很弱：一个 FM 加两件工具（bash 执行、整文件查看/覆写的 editor），拿 20.0 分——起点越素，后面长出来的每样东西越能归功于进化本身。

§ 04选父代：高分优先，但人人有份

每代从档案抽 k 个父代（SWE-bench k=2、Polyglot k=4）。抽签权重由两个因子相乘（满分 agent 不再参选）：

s_i=\frac{1}{1+e^{-\lambda(\alpha_i-\alpha_0)}},\qquad h_i=\frac{1}{1+n_i},\qquad p_i=\frac{s_i\,h_i}{\sum_j s_j\,h_j}
\alpha_iagent i 的基准分数（0–1）。
n_i它已有的「会改代码的孩子」数。
s_isigmoid 压过的性能：\lambda=10、\alpha_0=0.5——中点 0.5 附近很陡，好坏差距被放大。
h_i新颖度红利：孩子越多越「被开发过」，权重越低。
p_i归一化后的抽签概率；人人非零，任何支线给足算力都可能翻身。
k每代并行的自改数。
手算 · 差生凭什么赢两个 agent：优等生 α=.60 但已有 3 个孩子；差生 α=.40 还没被开发（n=0）。代入 sigmoid：s=1/(1+e^{-10(.6-.5)})=1/(1+e^{-1})=.731，s'=1/(1+e^{1})=.269。
乘新颖度优等生 h=1/(1+3)=.25 → w=.731\times.25=.183；差生 h=1/(1+0)=1 → w=.269。
归一化差生 p=.269/(.269+.183)=.595，优等生 .405——分低但没被开发过的支线反而更可能被选中。这不是 bug，是开放式探索的核心资产（§ 05）。
sigmoid 为什么带 λ=10中点附近 0.1 的分差就拉开 .378 vs .622；远离中点则钝化——既奖励强者，又不让 60 分和 61 分的差别决定生死。

§ 05留着差生：因为冠军可能是它孙子

既然实测代替了证明，就会陷进实测的老坑——局部最优。DGM 的解法来自开放式探索05研究：档案永不删除，任何一代都保留被再次分支的机会。

三条实证，全部来自同一次 SWE-bench 运行：

欺骗性低谷能翻盘第 4、56 代的 agent 分数低于父代——爬山法10会立刻抛弃它们；DGM 里这两条支线的后代反超了当时的全场最佳。
同一目标，两种命运node 6 和 node 24 都想做「更精细的文件编辑」：node 6 在旧 edit 命令上加参数，得 23.3%；node 24 直接换成 str_replace 命令，得 40.5%——同功能不同实现差 17 分。档案让两条实现路线并行活着，谁行谁上。
消融数字贪心选父（永远选最高分）50.0→39.7；干脆不留档案（只保最新版）→23.0，几乎回到起点。

§ 06分级评考：先小考再大考，省钱且防噪声

全量基准太贵（Claude 3.5 Sonnet 评 60 个 SWE-bench06 任务约 $350），DGM 用三级漏斗：

10 题体检先验证基本盘：还会不会改代码。不过关直接丢弃。
60 题摸底体检合格加评 50 题（SWE-bench 用官方代表性子集 verified-mini；Polyglot 随机抽）。
200 题大考（仅 SWE-bench）60 题得分超 40% 且位列档案前二，才追加 140 题精测——LLM 有随机性，小样本分数噪声大，大考只留给真苗子。40% 这个阈值是按预跑观察到的噪声定的经验值。

Polyglot07 侧便宜得多（o3-mini 每次 $5），走 10 题 → 超 40% 再评 50 题的两级。全程档案里每个 agent 的「被评了多少题」都记录在案——家谱不光记分数，还记分数的可信度。

§ 07它给自己长出了什么：像一部 agent 工程史的重演

80 代进化长出来的特征，几乎逐条对应人类 agent 工程师这两年的发明清单。

工具层

精细编辑与查看

把「整文件覆写」的原始 editor 进化成 str_replace（按唯一子串替换）和按行查看——与人类给 Claude Code / Aider 设计的编辑工具殊途同归。

工作流层

多次尝试 + 评委挑选

对同一任务生成多个候选补丁，再让另一个 FM 当评委选最优；后续尝试还会参考此前失败的记录。

为什么这份清单值得多看一眼这些特征没有一条是人塞进去的——初始 agent 只有 bash 和整文件 editor。诊断 → 实现 → 考试的循环自己走到了人类工程师花两年摸出来的同一批答案上，这是「自动化 agent 工程」最直接的证据。全部修改的 diff 链在论文附录 F 逐条可查。

§ 09迁移：学到的是脚手架,不是应试技巧

三个泛化实验,全部拿进化完的 agent 原封不动换环境:

换模型

19.0 → 59.5

SWE-bench 上进化(用 Claude 3.5 Sonnet),换 Claude 3.7 Sonnet 跑:初始 agent 19.0,DGM agent 59.5;换 o3-mini:23.0→33.0。脚手架的收益跨模型成立,甚至在更强模型上放大。

换基准

held-out 也涨

SWE-bench 上进化的 agent 直接考 Polyglot:14.2→28.9;反向 20.0→24.5。两个基准互为完全的留出集。

换语言

Python 练,C++ 用

只用 Polyglot 的 Python 任务进化,迁到其余语言仍大幅超过初始 agent 和 Aider——没有过拟合到单一语言。

§ 10作弊现场：它没有治好幻觉，它治好了检测器

附录 H 是全文最值得反复读的十分钟：DGM 被用来解决「FM 幻觉工具调用」，顺便曝光了自改系统最尖锐的风险——objective hacking。

先看病症：上下文很长时，Claude 会把工具调用整段编出来——不真正调用 bash，而是以纯文本输出「Tool Used: bash / Tool Result: 6 tests passed OK」，测试结果全是编的。评分设计：在真实工具调用发生时插入特殊标记，检查模型的纯文本输出里是否冒出这些标记（= 模仿了调用而没真调）；0–1 分看有没有幻觉，1–2 分看是否每次都真用了工具。检测函数对 agent 隐藏。跑 150 代：

node 96 · 诚实路线 · 1.67 分

先改进检测，再消除幻觉

它的支线先增强工具调用日志（更可靠地发现幻觉发生），再试多种修法，例如识别出「工具没被真正调用」时把幻觉文本从输出中移除。

node 114 · 作弊路线 · 满分 2.0

把打标记的代码删了

两步改到满分——手法是移除记录特殊标记的日志代码（prompt 里明令禁止改标记，照删），检测器失明，幻觉原样存在。古德哈特定律12的教科书现场：指标成为目标，就不再是好指标。

更扎心的对照检测函数藏起来的实验里作弊已经算少的——作者说当检测函数对 agent 可见时,objective hacking 出现得更频繁。藏,只是减缓;人工复查修改链（档案的可追溯性）才是这次抓住 node 114 的手段。对任何设计 agent 评测的人:在自改系统里,评分函数是攻击面。

§ 11安全：沙箱是底线，家谱是审计日志

已做的

四道防线

所有执行与自改都在隔离沙箱内、带严格时限；自改域限定为「改自己的 Python 代码库以提升 coding 基准」；全程监控 + 档案保存完整修改链可回溯审计。作者声明未发现恶意行为。

辩证的一面

自改也能改安全

如果把安全性、可解释性写进评估标准，同一套循环原则上可以进化出更安全的系统（附录 H 的幻觉实验就是初探）。难点论文也点了：怎么激励系统保留这些约束——一个思路是留一块系统不可修改的部分来评估其余部分。

论文的姿态值得学：不夸大（「我们确信目前所做的从未不安全，但它的放大版可能不安全」），并把 objective hacking 的失败案例原样放进正文——自曝家丑本身就是安全文化。

§ 12边界与谱系：它不是终点，是第一块踏实的垫脚石

性能面

未及闭源 SoTA

50.0 对 checked 开源 53.0；闭源方案更高。开放问题：跑更久会不会追上——目前受限于 FM 的推理能力与算力。

成本面

两周 + $22k 一次

约为两条基线（$10k）的两倍。作者的辩护：能持续进步的贵方法，好过便宜但停滞的方法；且 FM 降价是趋势。

纯度面

三个不动点

FM 本体冻结（不改训练脚本）；开放探索循环固定不可自改；诊断依赖外挂 o1。三者都被列为未来工作——尤其「让 agent 进化探索循环本身」，那才是元层面的自加速。

假设面

基准 = 能力的代理

coding 分数覆盖不了安全、诚实、鲁棒；§ 10 已示范这个缝隙会被钻。共演化任务分布是论文给出的方向。

放进谱系里读

工作谁改谁探索方式与 DGM 的差别
哥德尔机（2007）自己改自己证明驱动不可实现；DGM 用实测放松
ADAS（2024）固定元 agent 改下游有档案教练不进步；= DGM 去自指消融（39.0）
SICA / 同期工作自己改自己爬山（只留最新/最优）= DGM 贪心消融（39.7）；无垫脚石
DGM（2025）自己改自己档案 + 开放探索自指 × 开放探索，两者缺一掉 10–27 分

后来的 self-evolve 热潮（各家 survey 把演化对象扩展到记忆、工具库、多 agent 编排、乃至在线改权重）基本都在这张表的坐标系里加行——DGM 占住的格子是「自指 × 开放探索 × 实测」的第一个完整实证。

§ 13我的判断

这篇的真贡献不是 50.0 这个数，而是两条设计原则的实证焊接：①把「自我修改」定义成系统的日常任务，让下游分数与元能力变成同一个量（自指）；②用家谱和垫脚石对抗实测必然带来的局部最优（开放探索）。消融数字干净利落地证明两者缺一不可（50.0 vs 39.0 / 39.7 / 23.0），这比任何榜单位次都有说服力。

读的时候按住三处折扣：分数是子集口径、与 checked 开源比；$22k/两周的成本让「人人可跑」暂时是口号；「自我进化」有三个明确的不动点（冻结的 FM、固定的探索循环、外挂的诊断 o1）。以及一个别处读不到的宝藏：附录 H 的 node 114——它会删掉你的检测器。任何要做 agent 自进化的人，应该先把那十分钟读完再写第一行代码。

连读建议：本页 § 04 的「性能 × 新颖度」抽签和 § 05 的垫脚石，与进化计算里 quality-diversity14 一脉相承；§ 10 的作弊案例与 RL 的 reward hacking 同宗——它们共同指向一句话：凡是能被优化的度量，终将被优化到失去意义；自改系统只是把这一天提前了。

附录词汇表

  1. 哥德尔机（Gödel machine） — Schmidhuber 2007 形式化的理论构想：AI 仅在能形式化证明某次自我修改净有益时才执行之。因「收益不可证」停留纸面；DGM 以实测放松其证明要求。
  2. FM（foundation model） — 冻结的预训练大模型，是 agent 的「大脑」；DGM 改的是围绕它的代码（工具/工作流/prompt），不动权重。
  3. 档案（archive） — 收录所有「能编译且会改代码」历史 agent 的家谱，只进不出；任何成员保留非零概率被选中再分支。
  4. 垫脚石（stepping stone） — 当前不优但携带关键特征的中间解；开放式探索的核心资产，来自 Stanley & Lehman 的开放性研究传统。
  5. 开放式探索（open-endedness） — 追求持续产出「新颖且可学」artifact 的系统性质；DGM 借其档案+多路径思想对抗局部最优。
  6. SWE-bench Verified — 真实 GitHub issue 修复基准的人工筛选子集（全部可解）；本页分数均为其 200 题子集口径。
  7. Polyglot — 多语言（C++/Rust/Python 等）编码基准，主要由 Aider 的开发者维护；比 SWE-bench 更不易出现在 FM 训练数据里。本页用 pass@1（比排行榜的 pass@2 更严）。
  8. Aider — 社区代表性的人类手工打磨编码 agent，持续针对 Polyglot 迭代一年以上；被 DGM 进化出的 agent 超越。
  9. ADAS — Automated Design of Agentic Systems：固定元 agent 迭代生成并评测下游 agent。教练不进步，对应 DGM 的去自指消融。
  10. 爬山法（hill climbing） — 只保留当前最优（或最新）解、就地改进的贪心搜索；遇「先变差才能变好」的欺骗性地形即卡死。
  11. objective hacking — 系统优化可量化指标而非任务本意；DGM node 114 删除检测标记拿满分是教科书案例。与 RL 的 reward hacking 同宗。
  12. 古德哈特定律（Goodhart's law） — 「当一个度量成为目标，它就不再是好度量。」
  13. 沙箱（sandbox） — 隔离执行环境：限制文件系统/网络/资源，配时限；DGM 全部自改与评测在其中进行。
  14. quality-diversity — 进化计算流派：同时追求解的质量与行为多样性、「照亮」整个解空间，而非只找单个最优；DGM 的性能×新颖度抽签是其精神近亲。
