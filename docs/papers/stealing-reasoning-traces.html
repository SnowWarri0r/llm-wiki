Stealing
Reasoning Traces.

A. Panfilov · D. Schmotz · I. Shumailov · L. Beurer-Kellner · J. Schaeffer · A. Prabhu · J. Geiping · M. Andriushchenko · 2026

它用来回答一个很实际的问题：API 返回的隐藏推理明明是密文，为什么公开一份 agent 日志，仍可能把推理、密钥和个人信息一起暴露出去？

PATCH STATUS

这是已完成责任披露的漏洞复盘。作者称受影响 provider 已确认收到报告；截至 2026 年 8 月，论文图 1 的攻击已不能用文中方法复现。本页解释协议缺口、实验证据和修复边界，不提供可直接复刻的越权提示模板。

TL;DR

攻击者没有破解加密。他把一份合法、未改动的 reasoning envelope 搬到另一段会话或另一模型中；兼容 API 本来就会解密并处理它，再由较弱模型把内容重新生成出来。根因是 envelope 认证了“内容没被改”，却没有充分绑定“谁、哪次会话、哪种模型、排在第几步”。

SECTION 00先纠正四个最容易读错的点

NOT CRYPTO BREAK没有恢复密钥

真正解密仍由 provider 内部完成；攻击组合的是重放与模型转述。

INFERENCE具体密码协议未公开

“似乎使用全局共享 key”来自跨上下文兼容的行为证据，不是密码学逆向。

NO PLAINTEXT GT长度接近不是逐字真值

token 比例、定性细节与隐私泄漏共同支持高保真，但不能证明每个 token 完全一致。

第四点单独钉住：附录 B 的风格漂移、低困惑度与逐字概率都是行为探针。它们能说明“某些模型更容易被一小段来源推理带进相近轨道”，不能证明这些模型训练时偷用了 proprietary traces。

SECTION 01先看这封“密封交接单”：为什么 API 要把隐藏推理交给客户端

推理模型常先写很长的内部草稿，再只给用户短答案。下一轮若还要接着想，provider 要么替每个会话保存内部状态，要么把状态封进一份 opaque envelope15，让客户端代存并在下一次调用时传回。后者让 API 保持 stateless01，也方便压缩历史和切换模型。

关键区别在关联数据（associated data，AD）03：它不加密，但会参与认证。若 AD 里只有版本和 key ID，服务端只能确认“这是我签过的内容”；若还绑定 caller、session、model policy 和 turn，才有能力确认“它正在正确上下文里使用”。

这一节已有：envelope 解决了“隐藏内容 + 防篡改 + 客户端代存”。下一节要补：一份合法 envelope 到底能被搬多远。

SECTION 02三层兼容：从“自己换个对话”一路扩大到“换账号、换模型”

兼容本身有正常用途：编辑历史、压缩上下文、从昂贵模型降级到便宜模型，或者让网关自动换路由。漏洞来自兼容范围比业务需要更宽，而验证时又没有核对原上下文；这类不改消息、只把合法消息再次使用的问题叫 replay attack13。

论文区分两类攻击者。first-party attacker 自己请求强模型，拿到自己的 envelope，用于推理蒸馏或绕过强模型防护；third-party attacker 从公开 agent trace 拿到别人的 envelope，用于 secret extraction 或把被投毒的隐藏状态交给受害者恢复。

这一节已有：攻击材料如何跨边界流动。下一节要补：为什么另一模型能把“看见”变成“说出来”。

SECTION 03完整数据流只有两次调用：强模型产出，弱模型转述

这里最反直觉的一点是：source model 没有被直接要求泄露内部推理。它只完成正常任务并返回合法 envelope；真正的提取提示送给更弱、更便宜、但仍兼容该 envelope 的 decoder model。

作者选择 Claude Haiku 4.5、GPT-5.6 Luna 与 Gemini Robotics 1.6 作为 decoder。Claude 可沿用固定提取框架；GPT 需要 best-of-N05、失败回退，并把一次转录切成约 50 token 以内的小段；Gemini 最多取 20 组候选，再让 Flash 模型整合。流程差异本身就说明：这是一条模型生成链，不是“密文进去、明文必然唯一出来”的传统解密接口。

公开讲解的安全边界：论文附录给了 provider-specific 提示与规避细节。本页保留数据流、测量与防御，不复刻可执行的 jailbreak 模板。

SECTION 04没有 hidden plaintext，作者凭什么说“提取成功”

这条式子只回答长度是否对得上：

T_{\mathrm{ext}}转录文本重新编码后的 token 数。
T_{\mathrm{bill}}source API 报告并计费的 thinking token 数。
r两种长度之比；接近 1 表示长度接近。
e离 1 的绝对偏差；越小越接近。

作者在 120 个 Codeforces problems 上观察到多数点贴近 y=x，再用两类证据补强：decoded reasoning 明显比 displayed summary 细；有些 secret 只在 decoded reasoning 出现。正确结论是证据支持高保真恢复，而不是“已拿到可逐字核验的真实明文”。

这一节已有：提取证据的强弱边界。下一节要补：这条能力具体伤害哪四类对象。

SECTION 05四类风险不是散点：先看 envelope 属于谁

前四节已经说明 envelope 怎样被搬运与转述。风险可以用两个问题排成一张表：攻击者拿的是自己的块还是别人的块；目标是读出内容，还是让块继续影响后续行为。

为什么推理比答案值钱

答案只暴露终点，reasoning trace 还给出拆题、试错、核验与修正。假设可见答案 20 tokens，隐藏推理 1,980 tokens，训练序列长度从 20 变成 2,000，token 级监督密度约扩大 2000/20=100 倍。这不表示能力提升 100 倍，但解释了真实轨迹为何比同量短答案更有蒸馏价值。

论文估计：用 Haiku 4.5 处理 10,000 条、每条约 12k input 与 12k output tokens，名义 API 成本约 720 美元。若 traces 已由他人公开，攻击者甚至不用再向昂贵 source model 付费。

SECTION 07为什么“请帮我匿名化”反而可能把 secret 再写进隐藏层

用户让 agent 清理会话时，模型得先读到旧值，才能判断哪里要删。于是 visible answer 可能已经变成 API_KEY=[REDACTED]，hidden reasoning 却刚写下“需要删除的原值是……”。用户检查明文后公开 raw transcript，opaque block 仍跟着出去。

论文还指出：18 条 Opus traces 里 9 条在推导前先写答案，8 条 summary 也保留了这种顺序；有一条 summary 删除了“接下来要核验”的提醒。摘要能降低暴露面，却也会隐藏试错与不确定性，因此既不能用来证明 extraction 逐字正确，也不能替代对 opaque blocks 的清理。

发布 agent 数据最稳妥的规则：移除所有 reasoning、signature、thinkingSignature 与其他 opaque state 字段。只清洗可见文本无法覆盖模型真实读取的全部上下文。

SECTION 08附录 B 的问题不是“谁偷了谁”，而是“短前缀能把行为推多远”

作者把少量 decoded proprietary reasoning 放在 open-weight model 的推理开头，再让模型自由生成剩余推理和完整 visible answer。若输出变得更像 source，这证明一次推理中的条件敏感性；要证明训练时蒸馏，还需要训练数据、checkpoint lineage 或更强的因果证据。

完整 style 实验用 6 个 open-weight models、90 个问题（12 AIME + 78 Codeforces）、每个 prefill 条件重复 4 次，所以每模型每条件有 360 条；proprietary reference 每题只有 1 条，共 90。五个条件是 no prefill、self prefill、Sol 4 words、Opus 4 words、Kimi-K2.5 4 words。

多个模型在 Sol / Opus prefill 下与自己的 control 更容易区分，但真正朝 source reference 靠近的单元很少，AUC09也多在 .91–1.00，仍然很好分。Kimi-K3 与 GLM-5.2 的 reasoning length 在 prefill 后明显缩短，例如 Kimi-K3 从约 5,700 降到 Opus prefill 的约 2,500；这说明生成轨道被改变，不说明改变来自训练记忆。

作者自己的限制：漏洞修补后才做这组分析；样本小且偏 benchmark；decoded trace 是 fuzzy；serving precision、chat template 与 provider stack 无法完全控制。因此“unusual behavioral compatibility”是上限结论。

SECTION 09概率抽取与困惑度：一个问“能否逐字撞中”，一个问“读起来顺不顺”

角色 1 · 概率定义

独立采样 n 次，至少一次逐字生成目标 span：

z想逐字复现的目标 span，论文默认 16 tokens。
p_z一次 temperature-1 采样恰好生成 z 的联合概率。
1-p_z单次没有命中的概率。
(1-p_z)^nn 次都没命中的概率；用 1 减它得到至少命中一次。
设 p_z = 10⁻⁶，n = 1,000,000
P(hit) = 1-(1-10⁻⁶)¹⁰⁰⁰⁰⁰⁰
≈ 1-e⁻¹ = 0.632
平均要约 1/p_z = 1,000,000 次才进入“有机会撞中”的量级

论文用 teacher forcing10一次算出每个 token 的条件概率，再相乘得到 p_z。对 decoded reasoning 的 16-token spans，Kimi-K3 虽最容易，常仍需约 10^9–10^12 次查询；结果不支持实用的逐字记忆提取。visible answer 在完整 reasoning 条件下可能容易得多，这说明上下文能强力约束答案措辞，不等于 reasoning 被逐字记住。

角色 2 · 序列评分

困惑度衡量 scorer 觉得整段推理有多自然：

q题目；评分时始终作为已知条件。
t=(t_1,\ldots,t_{|t|})整段待评分 reasoning tokens。
t_{<i}第 i 个 token 前面的真实前缀。
p(t_i\mid q,t_{<i})scorer 给真实下一个 token 的概率。
\log把逐 token 概率的连乘变成可相加的 log probability。
-|t|^{-1}\sum取平均负 log probability；再 exp 回到等效分支数。
三个真值 token 概率 = [0.5, 0.25, 0.5]
平均负 log = -(ln.5 + ln.25 + ln.5) / 3 = 0.924
PPL = exp(0.924) = 2.52
等价验算：1 / (0.5×0.25×0.5)^(1/3) = 2.52 ✓

低 PPL11只说明“这段文字对 scorer 很顺”。论文热力图里 native trace 并不总在每个 scorer 下最低，作者也把 PPL 明确称为 coarse metric。把低 PPL 直接翻译成“模型训练时见过”会跳过最关键的因果环节。

SECTION 10防御不能只补一层：先缩小密文的合法使用范围

前面的漏洞链需要三件事同时成立：客户端持有可复制资产、资产能跨上下文通过验证、兼容模型愿意转述。防御要分别切断这三件事，而不是只训练模型“更会拒绝”。

最彻底的 stateful 方案把 reasoning 留在服务端，客户端手里不再有可搬运的密文资产。若业务坚持 stateless，authenticated-encryption 的 associated data 至少应绑定 caller identity 与 session；跨模型切换走受控重新签发，而不是默认全家族通用。

结构性上限：模型必须读懂自己的旧推理，才能保持多轮连续性。即使 transport encryption 完美，只要合法模型会被提示诱导转述，内容仍只是 semi-hidden。密码学能限制“谁能让哪种模型处理哪一块”，不能直接规定模型读完后怎样回答。

SECTION 11hash chain 每一项在管什么，为什么它仍拦不住整段重放

附录 A 的草案把下一块绑定到用户、会话与直接前驱：

\tau_n第 n 块 reasoning content；n 表示会话顺序。
\tau_{n+1}写入下一块关联数据的链式摘要。
H密码学 hash；输入变一点，摘要就应难以预测地改变。
\|拼接符号，把几段字节顺次接在一起；不是范数。
\mathrm{salt}_1,\mathrm{salt}_2额外随机值，用来隔离不同 hash 输入域。
\mathrm{user\_id},\mathrm{session\_id}把同一内容限制在原账号与原会话。
论文这里复用了同一个 τ 记号：右边的 \tau_n 是第 n 块推理内容，左边的 \tau_{n+1} 却是给下一块使用的摘要。实现里应当给 content 与 digest 分开命名；它不是“hash 之后变成下一段推理正文”。

P1（reasoning ordinality）只要求 X 在依赖它的 Y 之前；对话压缩时可以删掉一段，只保留剩余顺序。P2（full reasoning integrity）要求 Y 前面必须恰好是 X，任何中间块都不能删；它更强，却会让 compaction 后所有下游 hash 都要重算。论文建议用 Merkle tree12保留被压缩区间的 root，让 surviving spans 仍可验证。

这是 proposal，不是 deployed protocol。论文没有给 formal security proof、状态规模、fork/compaction 的完整 wire format，也没有 provider 采用情况。P3 leak monitoring 与 P4 single-use non-replayability 还需要服务端状态，不能只靠上面这条 hash 式子自动获得。

SECTION 13我的判断：这篇真正偷走的，是“加密等于安全”的错觉

STRONGEST EVIDENCE协议上下文缺口

同一合法块能跨 session / user / model 被处理，是整篇最直接、最可操作的系统证据。

MOST IMPORTANT NUMBER64 reasoning-only

它证明可见文本清洗并没有覆盖模型真实读取的全部上下文。

MOST LIMITED CLAIM谁做过蒸馏

style、PPL 与抽取概率三条线都不足以给训练来源定罪。

最值得带走的设计原则是：认证不仅要回答“这东西是真的吗”，还要回答“谁能在什么状态、什么顺序、什么权限下使用它”。stateless API 把服务端状态变成客户端资产，随之而来的可复制性、可分享性与可重放性必须一并进入威胁模型。

对数据发布者，行动建议更简单：公开 agent trajectory 时移除所有 opaque reasoning / signature fields。对 provider，context-bound AEAD、受控 model switching、legacy key retirement 与 model-level refusal 要一起做。任何一层单独承担全部安全责任，都会留下结构性缺口。

术语直达 · 点正文编号看人话解释

  1. Stateless API：服务端不为每段对话长期保存内部状态；客户端每次把恢复所需信息带回来。
  2. AEAD：Authenticated Encryption with Associated Data；同时提供保密与完整性，并认证一段不加密的上下文。详见概念页。
  3. Associated data：明文可见但纳入 tag 校验的字段，适合绑定 user、session、version 与顺序。
  4. Decryption oracle：攻击者不能直接拿到密钥，却能反复让一个合法组件处理密文并从输出侧获得信息；本论文的模型输出是模糊、随机的。
  5. Best-of-N：同一输入采样 N 次，再按某个准则选最合适候选；提高成功率，也提高调用成本。
  6. Reasoning-trace distillation：把老师的中间推理连同答案用作学生监督。详见概念页。
  7. Hidden prompt injection：影响后续行为的指令位于用户不可见的隐藏状态。详见概念页。
  8. Style drift：加入前缀后，输出的字符或词组统计发生可测变化；它描述行为变化，不等于训练来源证明。
  9. AUC：分类器把正例排在负例前面的概率；0.5 近似随机，1.0 表示完全可分。
  10. Teacher forcing：每一步都喂真实前缀，直接读取模型给真实下一个 token 的概率；这里用于评分，不是训练 decoder。
  11. Perplexity：平均负 log probability 取指数；越低表示 scorer 觉得序列越自然。详见概念页。
  12. Merkle tree：叶子逐层 hash 汇总成 root；保留 root 便能验证一段数据属于原集合，而不必长期保存所有叶子。
  13. Replay attack：不篡改合法消息，只在错误时间或上下文再次使用。详见概念页。
  14. Nonce：同一密钥下应保持唯一的一次性值；重复使用可能破坏具体 AEAD 算法的安全性。
  15. Reasoning envelope：客户端持有并回传的 opaque hidden-state block；它是协议资产，不应当作普通日志乱码。
