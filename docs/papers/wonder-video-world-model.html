Real-time interactive video world model

WONDER.

Jiacong Xu · Hanwen Jiang · Zhixin Shu · Kalyan Sunkavalli · Vishal M. Patel · Yiqun Mei

给一张图，边移动相机边探索画外；给一段视频，保留人物动作、换一条镜头轨迹重拍。Wonder 的重点不是某一个新模块，而是怎样把控制、记忆、蒸馏和实时运行一起拼成能工作的系统。

TL;DR

先把 6-DoF01 相机轨迹渲染成像素对齐的控制视频，再让四步因果 student08 从完整历史里只读少量相关 KV；三个分阶段学生和一项低频控制 GAN14 分别补容量与镜头漂移，项目页报告 16 FPS。

SECTION 00先拼完整系统：训练时很重，部署时只留生成链

Wonder02 有两种入口。I2V 从一张首帧往外探索；V2V 把已有视频当作“原事件”，在另一条镜头轨迹下重画。二者共用一套输入接口和同一组 student。

部署时存在

三个 14B student、相机控制渲染器、历史 KV 与摘要索引、四步去噪和 VAE05 解码器。

只在训练时存在

双向 teacher、DMD critic、控制判别器、真实训练视频和 teacher 预先计算的 ODE09 轨迹。

“世界模型”不要理解过头：它没有显式 mesh、物理引擎或物体数据库。它学的是“当前画面 + 历史 + 镜头动作 → 后续视频”的生成规律；画外内容是合理生成，不是还原真实世界。

SECTION 01为什么难：四个矛盾会互相放大

这四件事是串起来的：若控制在四步蒸馏后先变弱，记忆保存得再完整，也只是准确记住一条走偏的轨迹；若记忆只保滑窗，单块再漂亮，回到原地时也可能换了一扇门。

SECTION 02数据不是“收一堆视频”：必须把画面、相机和动作对齐

高频位姿抖动会教模型把“相机控制”理解成手抖，所以作者先做 Gaussian smoothing。倒放和变速不是纯增强：它们用同一段素材补反方向与不同速度，让动作分布不只集中在常见的平滑前进。

复现缺口：报告没公开视频总量、总时长、真实/合成混合比例、过滤阈值、VLM 淘汰率和数据授权明细。能读懂管线，不等于现在能等价复现。

SECTION 03Pixel-Space Coordinate Field：不只告诉模型“往右”，先把视觉后果画出来

纯相机位姿是一串数字，同一帧每个空间 token 都拿到一样的控制，模型还得自己学会“近物移动更快”。Wonder 的 Pixel-Space Coordinate Field03 先造一个与输入场景无关的合成空间，再沿目标轨迹用 OpenGL 渲染。

一个 3D 点怎样投到画面横坐标：

X点相对相机的横向位置
Z点离相机的深度
f焦距，控制投影放大程度
u点在图像上的横坐标
取 f=100，点 (X,Z)=(2,4)：u = 100×2/4 = 50
相机向右 1，点相对相机变成 X=1：u' = 100×1/4 = 25
屏幕位移 = 25−50 = −25（向左）

同样的点若离相机只有 Z=2 米：u = 100×2/2 = 100，右移后 = 100×1/2 = 50，位移是 −50
近处动 50，远处动 25；控制视频把“平移会产生视差”直接画给模型看。

它比位姿 embedding 多了像素对齐的视觉后果，又比输入点云更能外推：格点和环境球本来就是人工搭的完整空间，不会因为原图没拍到右边就断掉。

SECTION 04一条输入公式怎样同时装下 I2V 和 V2V

底座是 Wan2.1-I2V-14B。3D causal VAE 在空间压 8 倍、时间压 4 倍；DiT06 在 latent04 上工作，umT5 文本通过 cross-attention 注入。

先拆掉一个最大的坑：这条式子里有两种“时间”，别混。下标 \tau 是去噪时刻——现在噪声还剩多少，四步生成里它只取四个值；而 [\cdot]_T 的 T 是视频时间轴——先播 source、再播 anchor、再播待生成的目标段。整条输入 u_\tau 里，\tau 变一次只有目标段那一截跟着变，前两截永远是干净的。

SECTION 05Teacher → Student：为什么不能把双向模型直接拿来实时生成

双向 teacher

一段视频的 token 可以前后互看，去噪步数多，画质好。但它依赖“未来帧已经在场”，不能在用户刚移动镜头时立刻生成下一段。

因果 student

只看过去，可以按 chunk 流式续写。代价是四步跨度很大，而且会把自己的旧输出继续当历史，误差容易滚动累积。

那半句「RoPE 用 YaRN 外推」值得展开一下。RoPE 给每个 token 按位置编号旋转，模型只在 5 秒的位置范围上训过；horizon 拉到 20 秒后，后段 token 的位置编号是它从没见过的，注意力会读错相对距离。YaRN 的做法是按频率分段处理：管近距离关系的高频旋转保持不动（相邻帧的相对位置还是老样子），管远距离的低频旋转按比例压缩，把没见过的大编号折回训练时熟悉的区间——于是不用从头重训就能吃更长的序列。细节和数字例在 RoPE 那页的上下文扩展一节。

Self-Forcing07 的生活类比是练车：只在教练替你修正好方向后继续开，考试时一旦自己偏了就不知道如何救；训练时让 student 真正接着自己的旧输出开，才会遇到部署时的误差分布。

SECTION 06记忆的核心：摘要负责找，完整 KV 负责读

Wonder 不把旧帧压成几枚 token 后就丢掉原文。每个历史 chunk 保留完整 K/V，另存一个 pooled key 摘要。当前 query 先用摘要检索，选中后再拿对应 chunk 的完整 K/V 做 attention。

\mathcal A_t当前第 t 块真正激活的历史块集合
\mathcal N_r(t)最近 r 个块，论文取 r=2
\mathcal M(t)除首块和最近块外的中段历史
\bar Q_t,\bar K_c当前 query 与历史 chunk 的池化摘要
\operatorname{sim}摘要相似度函数；v1 未给具体形式
k从中段历史取多少个最相关块

整条读作：本轮激活 = 首块 \{0\}（永远保留的 sink）∪ 最近 r 块 ∪ 中段历史里摘要相似度最高的 k 块。TopK 那一项写的是相似度集合，取的是得分最高的那 k 个块本身。

中段 1–5 相似度 = [.15, .82, .20, .76, .11]
Top-2 = {2,4}
A_8 = {0} ∪ {6,7} ∪ {2,4} = {0,2,4,6,7}

历史涨到 100 块，本轮 active attention 仍只读 5 块；但 100 块的完整 KV 仍要存。
这不是“常量内存”。固定的是本轮计算量的大头；历史 KV 存储和摘要索引仍随时长增长。论文只描述 active rolling cache，没有证明无限时长下显存恒定。

SECTION 07为什么训练时就要随机断开远端历史

如果 student 训练时永远看完整历史，部署时突然只给 top-k，它会遇到没见过的输入分布。Sparse Context Forcing13 在 ODE 初始化阶段就随机丢掉可选远端边，让模型习惯“重要近邻必在，远处记忆不一定在”。

M^{(\ell)}_{ij}第 \ell 层中，query 块 i 能否读取 K/V 块 j
a(i,j)块 i,j 的基础因果关系
\mathcal R必须保留的边：自身、首帧、最近历史等
\mathcal O可以随机丢掉的远端历史边
b^{(\ell)}_{ij}一次 0/1 伯努利抽样
p_\ell第 \ell 层丢掉可选边的概率

式子里的 \mathbf 1[\cdot] 是指示函数：方括号里的条件成立就取 1，不成立取 0。所以整条式子只是在说两句话：这条边属于必留集合 \mathcal R → mask 恒为 1；属于可选集合 \mathcal O → mask 由抛硬币 b 决定。a(i,j) 就是「query 块 i 到 KV 块 j 这条边」本身，用来查它归哪个集合。

若 p_\ell=.6，每条可选边保留概率是 1-.6=.4。必须边不乘 b，所以永远为 1。这里的随机 mask 是训练课程；推理时真正用的是 §06 的确定性 top-k 检索，两者不是同一个动作。

SECTION 08Mixture of Students：仍做四步，只是每步换更合适的权重

第 1 步面对大噪声，主要搭房间与主体；最后一步接近干净图，主要补纹理和边缘。让同一套 14B 参数包办所有阶段，容量容易不够。Mixture of Students15 直接按固定去噪时刻分工，不需要 token router。

\circ函数复合：先算右边、把结果喂给左边，所以从右往左读
G_2^{(3)} 这类记号下标 = 用哪套学生权重，上标 = 这是第几次前向
x_{\tau_1}起点：噪声最大的那个去噪时刻的输入
教学用一维 latent：x_τ1 = 4
G1(4.0)=2.5 → G2(2.5)=1.6 → G3(1.6)=1.2 → G3(1.2)=1.0

网络调用仍是 4 次，不是 3 次；代价是要驻留 3 套 14B 权重。

论文说不增加 denoising latency，准确含义是没增加去噪步数。它没有证明显存不增加。为了不让三套学生各存一份视频历史，三者统一复用 G3 产生的自回归 KV cache。

为什么复用的偏偏是 G3 的缓存

论文只陈述了这个安排，没给理由；但从机制上看 G3 几乎是唯一合理的选择，有三层：

① G3 见到的才是「成品」。KV cache 存的是历史 chunk 的 key/value，给后面的生成当记忆用。四步接力里，G1 的前向发生在这个 chunk 还是一团大噪声的时候，G2 也只见过半成品；只有 G3 的最后一步是在接近干净的 latent 上算的。拿 G1 的 KV 当历史，等于让模型记住的是草稿；拿 G3 的，记住的才是它实际输出的那段视频。

② 这份缓存是白捡的。第 4 步前向本来就要跑，G3 算完顺手把 K/V 留下即可；换成 G1/G2 的版本反而要为「写历史」多跑一次前向。

③ 历史必须只有一个版本。三套学生各存一份，不止显存 ×3，更麻烦的是三个人记住的过去不一样——接力到中途换人时，对「刚才生成了什么」的理解就对不上了。

论文没展开的一层：attention 通常读的是同一套投影权重算出来的 K/V，G1、G2 去读 G3 写下的缓存其实存在权重错位。它能行得通，合理的解释是三套学生本就从同一个 teacher 复制而来、且 Self-Forcing 阶段就是在这个共享接口下 rollout 训练的——G1/G2 是学着读 G3 的历史长大的。但这一步论文没有明说，属于本页按训练流程做的推断。

SECTION 09GAN Control Regularization：DMD 修画面，这一项专门盯镜头

先看不加这一项会发生什么。论文描述的失败模式很具体：只用 DMD 训下去，student 镜头越跑越快、逐渐偏离目标轨迹，最终模糊甚至场景坍塌。根子在 DMD 的梯度口味：score 残差主要强调高频局部伪影——边缘、纹理这类逐点就能看出错的东西；而相机运动造成的是低频布局变化（整个画面往哪边流、流多快），这类错误在 score 差里拿到的梯度很弱。

那为什么不直接对镜头加一个逐像素 L2？因为画外内容本来就没有唯一正确答案，逐像素回归会把所有合理可能平均成一张模糊图。作者的选择是第三条路：拿冻结 teacher 的中间特征当观察器，用一个判别器只盯「镜头是否照着轨迹走」这一件事。

真实和 student latent 加同一份高噪声：

z_0真实视频 latent
\hat z_0student rollout latent
r/freal / fake 标签，不是指数
\epsilon两支共享的同一份高斯噪声
d^r,d^f判别器给真实/生成轨迹的控制一致性分数

「高」字是设计的一半。加噪本身就是一次低通过滤：噪声一大，边缘纹理这些高频细节最先被淹没，能在高噪声下存活的只剩大结构——画面布局、整体运动。所以在高噪声位置比较 real/fake，判别器想看纹理也看不见，只能去比镜头和布局；这正好和 DMD 的高频口味互补。至于两支共享同一份 \epsilon 的作用，见本节末尾的抵消式。

每张「低频差值图」是这样算出来的：

F_1冻结 teacher 第 1 层特征，当参照
F_{M_i}三个选定中层的特征，i=1,2,3
\eta_i,\eta_1线性投影，把两层特征对齐到同一通道空间
\psi_i带步长的卷积下采样，把残余高频纹理再压一遍

为什么是「中层减第一层」而不是直接用中层？第 1 层特征基本还是网络刚接住的输入本身——控制视频的通道刚刚注入、还没被消化；中层则是读懂之后的场景表示。两者作差，剩下的就是「网络把这段输入（含相机指令）消化成了什么」，输入里长得一样的部分被减掉了。三枚可学习的 register token 各自用 cross-attention 读一张差值图，把整张图的布局信息收进一枚 token，三枚求和后打出一个分数。

SECTION 1016 FPS 不是一个神奇 kernel：每层都在省重复账

先算预算：一个 chunk 只有约半秒

论文给了一个关键数：chunk 取 2 个 latent 帧。§ 04 说过 VAE 时间压 4 倍，所以一个 chunk 约合 8 个像素帧；16 FPS 下这是 0.5 秒的画面。也就是说，从收到镜头动作到吐出下一个 chunk，检索 + 4 次 14B 前向 + 通信 + 解码全加起来必须压进约半秒——项目页那句「0.5 秒 constant latency」正好就是一个 chunk 的滞后。论文没公开逐模块耗时，下面三本账讲的是每一项为什么能省。

COMPUTE 账：省的全是「重复付的钱」

编译并重放固定执行图——一次 14B 前向由几千个 GPU kernel 组成，每次 launch 都有 CPU 侧固定开销；四步生成每半秒重来一遍，这笔小钱乘起来不小。好在每个 chunk 的计算图形状完全一样，编译一次、之后按录好的模式重放即可。fused QKV 是把 Q、K、V 三次投影并成一次矩阵乘：省两次 kernel launch，更省两次把同一份输入从显存里搬进搬出。缓存 RoPE 与 timestep modulation 能成立是因为这两样都和画面内容无关：RoPE 的旋转角只由位置编号决定，算一次躺着用；timestep modulation（AdaLN 的 scale/shift）只由去噪时刻 \tau 决定，而四步采样的 \tau 是四个固定值——预计算四套查表即可。FlashAttention-321 负责让 attention 本身不把 N\times N 中间表写进显存。

CACHE 账：凡是不随本轮变化的都别再算

历史 chunk 的 self-attention K/V（§ 06 的记忆本体）、文本 cross-attention 的 K/V（prompt 全程不变，编一次用到底）、检索用的 pooled key，都算一次就存。输出端用 Tiny VAE——一个小得多的解码器，条件输入和生成结果都用它编解，把每个 chunk 的解码时间从预算里压下去。

MULTI-GPU 账：为什么 FFN 按序列切、attention 却按 head 切

这是三本账里最值得懂的一条。FFN 对每个 token 是独立的——一个 token 过 FFN 不需要看别的 token，所以把序列切成几段分给几张卡，各算各的零通信。cross-attention 同理：video token 只看文本 K/V（很小，每卡复制一份），token 之间互不相干。但 self-attention 里每个 token 要看所有 token，按序列切就得把别人卡上的 K/V 都搬过来，通信立刻爆炸；好在 head 之间是独立的——改成每张卡拿全部 token 的一部分 head，卡内自己算完整 attention，零跨卡读取。

4 张卡、16 个 head、N 个 token：
FFN 布局　　　每卡 N/4 个 token × 全部 16 head 的通道
attention 布局　每卡 N 个 token × 4 个 head

两种布局之间靠 NCCL All-to-All 互倒：每张卡把手里的数据按目标卡切成 4 份，
同时收下其他卡发来的 4 份——一进 self-attention 倒一次，出来再倒回去。
KV cache 也按 head 分片存，正好躺在 attention 布局里，检索读取不用再搬。

超过训练窗口之后：位置编号折回去

训练最长只见过 20 秒，往后生成时 frame index 会超出 RoPE 见过的范围（§ 05 的 YaRN 管的是 teacher 拉长课程，这里是推理期的另一道保险）。做法是把 active cache 组织成 [sink, top-k, recent]，再按相对距离把这几块的编号重新映射回训练见过的区间——反正本轮只有这几块在场，编号只要保住它们之间的先后和远近关系即可。论文没给具体映射公式，只说 by relative distance。

训练侧那串配置也各有各的账：FSDP216 把参数/梯度/优化器状态分片省显存；sequence / tensor parallel 就是上面推理侧那两种切法；activation checkpointing 不存中间激活、反传时重算，拿计算换显存；梯度累积用多个小 batch 凑出 global batch 64；replayed back-propagation 用于给自回归 rollout 求导时省显存。公开配置为 32 张 H200。

这个「重放」容易读歪，两个常见误解先排掉：省下的不是梯度，是中间激活——梯度本来就是边算边往回传、不需要囤，要囤的是反传时用到的每层前向激活；它也不省计算，反而主动多算——rollout 先整体跑完不留计算图（只留各段输出这类最小状态），反传时一段一段重放：这段重新前向、这次留激活，算完梯度就丢，再下一段。峰值显存从「整条 rollout 的激活」降到「一段的激活」，代价是前向整体多跑一遍——跟 activation checkpointing 同一笔买卖，只是把范围从单个网络的层间推广到整条 rollout 的段间。论文只给了引用（Hong et al. 2025）没讲机制细节，跨段梯度是否截断也没说。

项目页的性能口径：16 FPS、0.5 秒 constant latency。论文没有同时给出分辨率、推理 GPU 型号与数量、显存、batch、首块延迟和各模块耗时，因此不能拿这两个数直接和单卡模型横比。

SECTION 13一分钟复盘：把四个问题和四个解法一一对上

CONTROL位姿太抽象

→ 渲染 3D 格点 + 环境球控制视频，把平移视差与旋转方向画出来。

MEMORY全读太慢，滑窗会忘

→ 完整 KV 全保留，pooled key 只负责检索，当前读 sink + top-k + recent。

SPEED / CAPACITY四步学生太吃力

→ ODE 初始化 + Self-Forcing/DMD，再让 G1、G2、G3 分阶段接力。

DRIFT镜头误差越滚越大

→ 冻结 teacher 提取低频控制特征，用相对 GAN 单独给镜头监督。

最值得记住的设计：“摘要只负责找，完整 KV 才负责读”；“四步没有减少，只是换三套权重接力”；“相机控制不是再塞六个数，而是先把六个数造成的画面变化渲染出来”。

术语直达表

  1. 6-DoF：相机三维位置 x/y/z 加绕三个轴的旋转，共六个自由度。
  2. World model：根据观察和动作预测后续状态；Wonder 用生成视频隐式表达状态，不是显式物理引擎。
  3. Pixel-Space Coordinate Field：把相机轨迹在人工 3D 格点与环境球中渲染成像素对齐控制视频。
  4. Latent：VAE 压缩后的特征空间；比原像素小，生成模型主要在这里去噪。
  5. VAE：把视频压成 latent，再把生成好的 latent 解码回视频的编码器—解码器。
  6. DiT：Diffusion Transformer，在带噪 latent 上用 Transformer 预测去噪方向。
  7. Self-Forcing：训练时让模型接着自己的旧输出生成，提前经历部署时的滚动误差。
  8. Teacher / student：高质量但慢的模型提供训练目标，快模型学习它的分布与轨迹。
  9. ODE initialization：先让四步 student 模仿 teacher 的概率流 ODE 在四个时刻的落点。
  10. DMD：Distribution Matching Distillation，用真实分布与生成分布的 score 差更新少步生成器。
  11. KV cache：保存旧 token 的 key/value，后续生成不用重新计算整段历史。
  12. Sparse attention：只让当前 query 读取少数被选中的历史 token 或 chunk，减少本轮计算。
  13. Sparse Context Forcing：训练时随机断开可选远端历史边，让 student 适应推理时的稀疏上下文。
  14. GAN control regularization：从冻结 teacher 的低频特征判断镜头是否听话，并把梯度补给 student。
  15. Mixture of Students：按固定去噪时刻让三套完整 student 接力四步，不是 token 级动态路由。
  16. FSDP2：把模型参数、梯度和优化器状态分片到多张 GPU，降低单卡训练显存。
  17. RPE：Relative Pose Error，比较相邻相机位姿变化是否和目标轨迹一致，越低越好。
  18. Umeyama alignment：用闭式解把估计轨迹旋转、平移并统一尺度，再公平计算轨迹误差。
  19. RoPE：按 token 位置旋转 query/key，让注意力点积天然携带相对位置；每个维度用不同旋转频率。详见 RoPE 一页。
  20. YaRN：RoPE 的长度外推方案。按波长分段：管近距离的高频不动，管远距离的低频按比例压缩回训练见过的范围，再配注意力温度补偿；不重训就能在更长序列上读对相对位置。
  21. FlashAttention-3：精确 attention 的 IO 优化——分块计算、不把 N\times N 中间表写回显存，并利用 Hopper 架构的异步执行；算的还是同一套 attention。
