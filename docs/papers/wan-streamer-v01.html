一个模型
边听边看，也边说边画

给实时视频助手用：用户还在说话，它仍能看见、听见并做出可见反应；智能体自己说话时，用户也能随时打断。v0.1 把这些要求写进训练结构，而不是用一串外部模块临时拼起来。

TL;DR　双方的文字、声音和画面共六路信号，被排进一条因果时间线。文本预测下一个 token；音频和视频 latent 联合做条件流匹配；每 160 ms 推进一个单元。新生成的干净 latent 立即写回历史，并在下一拍解码播出。原型在 192×336、25 FPS 下报告约 200 ms 模型侧延迟，量化质量证据仍很少。
00 · Read this first

先排除四种误读

01

不是一块裸 Transformer

仍有文字 tokenizer、因果音视频编码器、VAE01和解码器。统一的是中间状态与交互建模。

02

文本不做去噪

离散文字走 next-token02；连续音视频 latent 才走 flow matching。

03

不是两套独立模型

Thinker–Performer03是同一模型上线时的两卡分工。

04

不是完整 SOTA 证明

自然倾听、打断、主动说话主要靠 demo；没有统一量化 benchmark。

01 · The real problem

级联数字人为什么“能说话”却不像在交谈

常见管线是 VAD → ASR → LLM → TTS → 动画。每个模块各自都能很强，但交接处会等待；文字还把语气、停顿、目光和手势压扁成一句话。

等待

上一环没吐完，下一环不开工

识别、思考、合成、渲染逐段排队，首个可感知回应越来越晚。

误差

识别错，整条链跟着错

文字中间表示丢掉声调和视觉线索，后面的语音与动画无法补回。

行为

没人统一学习“何时回应”

倾听、停顿、重叠、让出话轮和打断落在外部规则里，模型学不到完整行为。

关键转折全双工04不是“把响应再压快一点”。用户说话时，智能体仍要生成倾听表情；智能体说话时，感知链也不能停。这要求训练和推理都从一开始遵守原生流式契约。
02 · System map

完整拼图：六路信号，只有一份持续更新的历史

先只认顺序，不要求现在理解每个名词。用户的文字、声音和画面先被编码；统一 Transformer 更新状态；文字和连续 latent 走两种输出目标。干净音视频 latent 一生成就写回历史，再由解码器变成声音和画面播出。

这三条约束合起来就是原生流式契约：所有组件只能读取当前已经到齐的单元与过去，不能偷看尚未到达的后续单元；新观测立即能用；生成结果马上提交回历史。

为什么 VAE 和解码器也必须因果

只把 Transformer 改成流式还不够。若音视频 VAE 编码当前画面时仍要等未来帧，或者解码器必须拿齐整段 latent 才开工，等待时间会从前后两端重新冒出来。因果流式 VAE要求每个时间点只用当前已经到达的内容与过去缓存；论文明确了这条约束，但没有公开卷积核、压缩率和缓存结构。

03 · Probability

那条条件概率，只是在写“每一段都接着历史算”

先定义符号，再看公式。这里没有扩散，也没有训练损失；它只描述整段交互怎样按时间拆开。

u_k=(u_k^t,u_k^a,u_k^v)第 k 个单元到达的用户文字、音频和视频。
y_k=(y_k^t,y_k^a,y_k^v)第 k 个单元生成的智能体三模态回应。
K整段交互包含多少个流式单元；是正整数。
\theta模型全部可训练参数；下标表示概率由这套参数给出。
u_{\le k}用户从开始到当前单元的全部观测。
y_{\lt k}智能体在当前单元之前已经生成并写回的历史。
p_\theta(y_{1:K}\mid u_{1:K})=\prod_{k=1}^{K}p_\theta\!\left(y_k^t,y_k^a,y_k^v\,\middle|\,\substack{u_{\le k}^t,u_{\le k}^a,u_{\le k}^v,\\y_{\lt k}^t,y_{\lt k}^a,y_{\lt k}^v}\right)
左边问什么已知整段用户输入，整串智能体回应出现的概率是多少。
右边怎样算第 k 段只根据已经到达的用户信号和已经提交的回应历史，算当前三模态回应的条件概率。
为什么相乘概率链式法则把整条路径拆成逐段条件概率；不是说各段互相独立。
数字验算三段概率为 0.8、0.6、0.5，整条路径为 0.8\times0.6\times0.5=0.24。
04 · Block causal

160 ms 一块：块内并行，块间不偷看未来

文字按 token 一个接一个预测；同一小段音视频却包含很多同时刻附近的 token。若全部强行逐 token 串行，GPU 并行度太差。块因果注意力05把“时间先后”放在块之间，把“并行计算”留在块内部。

一秒是 1000 ms，所以 25 FPS 对应 1000\div25=40\ \mathrm{ms} 一帧；再算 160\div40=4，一个 160 ms streaming unit06正好包含 4 帧。块越长，模型看到新用户信号的机会越少；块越短，调度、通信和解码次数越多。160 ms 是论文报告的运行点，不是普适最优值。

05 · Two output targets

为什么文字预测编号，音频和视频却要学速度

离散输出

文字：从有限词表选下一个 token

模型给每个词表编号一个概率，用交叉熵07提高正确编号的概率。

连续输出

音视频：从噪声沿速度场走回 latent

像素压缩后的 latent08是连续向量，无法把所有可能值列成词表。

文字这边可以直接手算。若 p_{\mathrm{true}} 表示模型分给正确 token 的概率，单个位置的交叉熵就是：

\mathcal L_{\mathrm{text}}=-\log p_{\mathrm{true}}
为什么前面有负号\log 是自然对数。正确 token 概率为 0.8 时，损失是 -\log(0.8)\approx0.223；概率只有 0.1 时，损失变成 -\log(0.1)\approx2.303。概率越低，惩罚越大；训练就会把正确编号的概率往上推。

两条路共享同一份干净历史。声音和画面还一起进入统一 Transformer，所以语调、口型、动作和场景变化在解码之前就能互相影响。这里的“联合”是建模结构，不等于论文已经用量化实验证明每类音画同步都准确。

06 · Flow matching

条件流匹配：先造直线路径，再让模型回归速度

本节沿用一组标量，从路径一直算到损失。真实模型处理的是高维音频和视频 latent，算法相同。

m\in\{a,v\}当前讨论音频 a 或视频 v。
z_0^m数据给出的干净目标 latent；下标 0 指路径的数据端。
\epsilon^m\sim\mathcal N(0,I)从标准高斯采样的噪声；不是模型误差。
\tau\in[0,1]流路径上的位置；0 在数据端，1 在噪声端。
c_k当前已经到达的用户观测与已经提交的智能体历史。
f_\theta统一 Transformer 给出的速度预测。
\begin{aligned}z_\tau^m&=(1-\tau)z_0^m+\tau\epsilon^m,\\[4pt]\frac{\partial z_\tau^m}{\partial\tau}&=\epsilon^m-z_0^m\end{aligned}
路径中间点z_\tau=(1-0.25)\times2+0.25\times(-1)=1.5-0.25=1.25
路径导数\epsilon-z_0=-1-2=-3。它描述 \tau 增大时怎样从干净端走向噪声端；负号来自数值从 2 降到 −1。
生成时反走生成要让 \tau:0.25\to0，所以 \Delta\tau=-0.25。用正确速度反推：1.25+(-3)\times(-0.25)=2，正好回到干净端。
模型预测假设 f_\theta=-2.4，速度绝对值比目标少 0.6；同样反走只到 1.25+(-2.4)\times(-0.25)=1.85，离干净目标还差 0.15。

速度有了，损失只需要衡量预测与目标差多少：

\mathcal L_{\mathrm{FM}}^m=\mathbb E_{\epsilon^m}\left[\left\|f_\theta(z_\tau^a,z_\tau^v,c_k,\tau)-\frac{\partial z_\tau^m}{\partial\tau}\right\|_2^2\right]
\mathbb E_{\epsilon^m}[\cdot]换不同噪声样本重复计算，再取平均。
\|r\|_2^2误差向量每个分量先平方再相加；标量时就是 r^2。
\partial z_\tau^m/\partial\tau上一条路径公式求出的目标速度，不是另一个网络。
\mathcal L_{\mathrm{FM}}^m模态 m 的 flow-matching 损失；越小越接近目标方向。
代入上面的同一组数((-2.4)-(-3))^2=0.6^2=0.36。若视频分支误差为 0.5，它的平方损失是 0.25；等权相加的教学总损失为 0.61。论文没有公开两种模态的实际权重，不能把等权当成实现事实。
07 · Training

三阶段训练：先会各项能力，再练交谈，最后压缩推理

训练数据先分三类

理解

图像、音频、视频理解，文字对话、ASR、TTS 与音频对话，负责把输入变成共享因果上下文。

生成

图像、音频、视频及联合音视频生成，负责学会连续 latent 的生成与跨模态条件。

双工交互

双方的文字、声音和画面都能交错出现，专门训练同时感知、表达和管理话轮。

数据边界论文只列了任务类型，没有公开样本量、来源、比例与清洗方法。因此这里只能解释三类数据各自负责什么，不能判断它们各自贡献了多少。

为什么还要 rolling distillation

若学生训练时永远读取真实历史，部署时却读取自己生成的历史，轻微色偏和姿态误差会越滚越大。self-forcing10让学生连续 rollout；distribution matching11再把学生轨迹往教师分布拉。把画面宽度归一化为 1，假设学生每段都把脸向右偏 0.1：单段训练每次只看见 10% 的偏差；连续三段会真的暴露 0.1\to0.2\to0.3，也就是 10% → 20% → 30% 的累积漂移。

论文没有给蒸馏公式公开文字只到“强教师 + CFG + 更多步 → 少步学生；再用 self-forcing 与 distribution matching 做 rolling distillation”。教师/学生步数、CFG scale、rollout 长度与完整损失都没公开，不能补一条看似合理的“官方公式”。
08 · Serving

两卡流水：第 k 拍生成，第 k+1 拍才解码播出

训练时是一套模型，上线才按工作性质拆开。Thinker 做短而急的感知、状态、KV cache12与解码；Performer 只跑昂贵的 flow-matching solver13。

Thinker 在第 k 拍收到当前用户单元，同时解码上一段 y_{k-1}；Performer 依据新 KV 生成 y_k。所以图里的箭头不能把“生成 y_k”直接连到同拍的“解码 y_k”。

09 · Three clocks

160 ms、200 ms、550 ms 分别在算什么

吞吐节拍160 ms

Performer 计算加通信要压进一个单元，否则队列持续积压。

模型响应≈200 ms

输入经过编码、状态更新、latent 生成和解码的 signal-to-signal14路径。

远程总计≈550 ms

约 200 ms 模型侧 + 论文预留的 350 ms 双向网络预算。

流水线类比工厂每 160 ms 能下线一件，不代表一件产品从进厂到出厂只花 160 ms。多件产品在不同工位重叠，稳态节拍可以短于单件全路径时间。
10 · Evidence

实验真正证明了什么

结论证据级别怎样读
192×336、25 FPS、160 ms 单元明确报告v0.1 proof of concept 的运行点。
模型侧约 200 ms两 GPU 路径从用户单元可用到对应音视频单元解码完成。
远程总交互约 550 ms带假设额外加入 350 ms 双向网络预算。
自然倾听、打断、主动说话定性演示论文描述并给 demo，没有成功率或人评。
比所有竞品更快不能直接下结论竞品混有模型延迟、first packet、TTFB、FPS 和渲染阶段口径。

两张对比表为什么不能只挑最小数字

语音系统可能报告 model latency、first token、first packet 或 API TTFB；视觉系统常报告 20–40 FPS、首帧等待或 audio-to-visual delay。前者不输出同步视频，后者往往不包含外部 ASR、LLM 和 TTS。Wan-Streamer 报的是完整音视频响应路径，但这也不是第三方统一硬件复测。

系统原文列出的数字数字覆盖到哪
Moshi理论 160 ms；实际模型约 200 ms原生全双工语音，不生成视觉智能体。
Qwen3 / 3.5-Omni首包 234 / 547 ms；3.5 Flash 235 / 426 ms，Plus 435 / 651 ms首包口径；没有同步视觉头像输出。
X-Streamer两张 A100 上 25 FPS多模态视频流；未公开绝对响应延迟。
VASA-140 FPS，preceding latency 170 ms音频驱动的人脸渲染器，不含对话推理和用户视觉感知。
AvatarForcing（Cui 等）34 ms/帧；音频到画面 0.51 s流式说话头像组件，不是完整感知—对话链。
Wan-Streamer25 FPS；模型侧约 200 ms；含网络约 550 ms文字、音频、视频输入输出共用一条端到端因果链。
相关工作分成三条线全双工语音模型解决“边听边说”，但不生成可见动作；流式头像解决“画面跟着声音动”，但通常依赖外部对话模型；少数端到端音视频智能体与 Wan-Streamer 范围最接近，却大多没有统一的 signal-to-signal 延迟。论文把它们放进同一章，是为了比较覆盖范围，不是声称所有数字能直接排名。
11 · Qualitative behavior

空闲、倾听、打断、主动开口：目前都是什么证据

空闲

保持视线、姿态、呼吸和微表情，不冻结成头像。

倾听

根据用户声音与画面出现点头、目光变化和姿态反馈。

打断

自己说话时仍持续感知，用户插话后可停止、缩短或转向。

主动

看到新物体、动作或表情时，可以不等明确口令就评论。

这些行为说明统一时间线有合理的能力出口，但论文本身没有给长时身份一致性、打断响应率、错误主动发言率、唇音同步或自然度人评。正确结论是“定性样例支持机制可行”，不是“已由 benchmark 证明接近真人”。

14 · Verdict

我的判断：系统主线讲清了，复现配方远远不够

v0.1 最有价值的不是某个单独模块，而是把“当前输入立刻可用、说话时继续感知、生成结果写回历史、昂贵求解与状态更新重叠”连成一套训练—部署契约。公式、三阶段课程和两卡时序都足以让人理解路线。

但它仍是一份原型系统报告。模型尺寸、数据账、硬件账、蒸馏公式、消融和量化质量都没公开，无法照着论文逐项复现，也无法证明自然度全面优于现有系统。更准确的定位是：它证明“一个端到端全双工音视频模型可以跑起来”，还没有证明这套配方已经是最佳解。

术语直接补全

  1. VAE：把高维音频或视频压成连续 latent，再从 latent 还原；v0.1 要求时间方向严格因果。
  2. Next-token prediction：根据已知 token 给词表里下一个编号分配概率。
  3. Thinker–Performer：同一模型的部署分工；前者管感知、状态和解码，后者管连续 latent 生成。
  4. Full duplex：输入与输出同时保持工作；模型说话时仍能听见和看见用户。
  5. Block-causal attention：同一时间块内部并行互看，后面的块只能读取当前与过去。
  6. Streaming unit：固定时长的流式工作单元；本报告为 160 ms，即 25 FPS 下 4 帧。
  7. Cross entropy：提高正确离散 token 概率的训练损失。
  8. Latent：VAE 压缩后的连续表示；比原始波形或像素更适合生成。
  9. CFG：把有条件和无条件预测的差值放大，提高条件遵循；代价通常是两次前向。
  10. Self-forcing：训练时让模型继续读取自己生成的历史，贴近真实部署输入。
  11. Distribution matching：把学生生成分布向教师或真实目标分布拉近，而不只逐样本对齐。
  12. KV cache：attention 历史 Key/Value；新单元追加，过去不用整段重算。
  13. Flow-matching solver：沿模型预测的速度场做若干更新，把噪声变成干净 latent。
  14. Signal-to-signal latency：用户信号进入，到对应可感知音视频回应完成解码的全路径时间。
